## Summary

InputSystem 是本项目唯一的**战斗移动输入路径**。MVP 使用 Godot 4.7.1 内置 `VirtualJoystick` 的 Dynamic 模式和四个专用、无 InputMap event binding 的 action，将单拇指拖动转换为二元移动方向（停止或满速），再写入预分配 `MovementIntentCarrier` 供 PlayerController 在同一 `MOVEMENT_COMMIT` phase 消费。普通暂停时，InputSystem 在 pause barrier 冻结前关闭 gameplay gate、开启覆盖完整movement rect且由Host唯一持有的typed new-press shield、释放四个 action 并原子清零 carrier，但不冒充已取消内置节点私有的 touch claim；已归属VJ的旧 movement touch仍按Godot touch-focus路由终止事件，暂停期间由shield接收的新movement touch也必须matching release/cancel后才能允许resume开放movement ingress。`callbacks_armed`只表达adapter生命周期，`runtime_ingress_armed`只表达ACTIVE movement/VJ新press写入权，独立的`shield_bank_service_enabled`只在曾进入ACTIVE后的LOCK_PENDING/FROZEN/RESUME_LOCKED服务consumer-closed touch ownership；三者不得互相替代。resume事务期间新落入shield的合法触点只会使事务在安全边界回Paused或完成已不可逆publish后无lease等待终止，不得升级为technical fault；回Paused时保留唯一resume intent，terminal后自动单次重试且不重复choice effect。每个resume attempt固定捕获input/background revision；不可逆点后的publish、cleanup、held-drain与ACTIVE提交都必须复核该快照，新invalidation只能在资源收敛后进入fault，不能被激活尾段清除。最终激活采用persistent root Window物理屏障协议：项目bootstrap在BOOT冻结Input accumulated=false、只读确认ProjectSettings agile=false，并在任何项目input target激活前一次性flush历史buffer，避免全局Input缓冲把gate-held期间到达的事件延迟到物理开放后；GameRoot再按`PRE_ACQUIRE→SET_TRUE_IN_FLIGHT→GATE_HELD→reasoned release`矩阵独占persistent root Window。setter-in-flight时合法ScreenTouch由shield containment：loading只PREACTIVE_DISCARD，resume按现有FSM记录held并由first observer回drain；只有true setter返回后的`GATE_HELD`区间保证Viewport零投递。Input与GameRoot完成局部ACTIVE提交后，最终`gui_disable_input=false`才是唯一物理开放点。BATTLE_LOADING把callbacks连接、shield service与runtime ingress开放分离，并使用同一Viewport阶段矩阵完成`IDLE→ACTIVE`；加载期touch只丢弃、不形成held或跨ACTIVE晋升。APP_BACKGROUND 不依赖系统补发 release：GameRoot 在任何 foreground gameplay tick 前要求 `VirtualJoystickHost` 重建其唯一内置节点、推进 `gesture_epoch`并保持 carrier 为 ZERO；每个新的background revision都必须由当时最新的readiness确认，恢复后的下一次 OS press 才是 fresh movement press。

Meta UI 的keyboard/mapped-gamepad导航是独立的app-root presenter输入域，只能按八行`MetaUiInputActionManifestV1`生成typed UI command，永不写`MovementIntentCarrier`。因此“raw gamepad不影响战斗移动”不等于“项目不支持gamepad UI”。

### Steam-first active profile（2026-09-10）

当前正式生产目标是 Steam PC（Windows 优先）。PC 战斗 profile 使用 `move_left/right/up/down` 四个 InputMap action：键盘 WASD 与映射后的手柄左摇杆统一由 InputSystem 采样并写入同一 `MovementIntentCarrier`；触摸 profile 的 `touch_move_left/right/up/down` 继续保留为空事件 action，作为 Android/iOS/小游戏后续适配入口。下文明确写“仅触摸”“portrait”或“键盘/gamepad不得改变movement carrier”的条款，若未特别标注 Steam profile，均属于移动端 future-port 合同，不构成 Steam 首发阻断条件。

## Overview

玩家在竖屏设备interactive safe viewport下方45%的移动输入区内，用左手或右手单拇指按下并拖动 Dynamic 虚拟摇杆；所有攻击和法术自动释放，无普攻、闪避或主动大招键。内置 `VirtualJoystick` 是四个专用 action `touch_move_left/right/up/down` 的唯一生产 writer；四个 action 必须存在但 event list 为空，生产配置关闭 mouse-to-touch emulation，项目其他代码不得对其调用 `Input.action_press`。`VirtualJoystick.deadzone_ratio` 是唯一 deadzone owner；`Input.get_vector(..., deadzone=0.0)` 不再施加第二层 deadzone。InputSystem 每个 `MOVEMENT_COMMIT` tick 读取 action vector，归一化后写 carrier，不读取不存在的 `VirtualJoystick.output/input_vector` 公共属性，也不重建 thumb/origin 像素公式。

InputSystem 同时参加 `POST_DEFERRED_BARRIER`：GameRoot latch pause intent 后、调用 SpatialGrid pause 且 SceneTree 真正冻结前，必须先调用 `cancel_input(reason, tick_revision)`。该操作关闭 fresh-press gate、经唯一helper释放四个专用action并把carrier写为`{ZERO,false,-1,current_tick}`；普通暂停若内置节点仍持有claim，则gesture gate进入`WAIT_IGNORED_RELEASE`，只有其`released`信号后才回到`WAIT_FRESH_PRESS`。`RESUME_PREPARING`在resume transaction前由GameRoot显式发布RESUME_LOCKED并再次cancel。APP_BACKGROUND或safe geometry invalidation另在consumer-closed preflight调用`VirtualJoystickHost.ensure_rebuilt_after_invalidation(input_rebuild_revision,geometry_snapshot,tick_revision)`，通过每个revision至多一次的离树candidate替换消除私有claim或静默reset分叉；旧节点的迟到signal因`gesture_epoch`不匹配而被忽略。

`MetaUiNavigationCommandV1={schema_version:i32=1,screen_id:i32,screen_generation:i64,layout_generation:i64,input_event_id:i64,command_kind:i32,target_node_id:i64}`是Godot主线程presenter-local导航carrier；`command_kind={FOCUS_NEXT=1,FOCUS_PREVIOUS=2,FOCUS_LEFT=3,FOCUS_RIGHT=4,ACTIVATE_FOCUSED=5,BACK=6,INCREMENT=7,DECREMENT=8}`。前四类只移动当前focus并产生0业务命令；ACTIVATE/BACK/INCREMENT/DECREMENT验证实际node后才转换为各owner的typed business command。它不是`AccessibilityActionCommandV2`，native accessibility已携带target node，不伪造focus方向。

## Player Fantasy

**玩家幻想：手指即身法。**

拖动越过唯一死区后，最迟在下一个 InputSystem physics tick 输出该方向；方向反转和松手也最迟在下一个 tick 反映到 carrier。InputSystem 域内不加入插值、平滑、阻尼或滤波。玩家被三面围堵时，能用任一手的单拇指在下方移动区起按、转向并穿过缺口；若多层死区吞掉微调、暂停恢复产生幽灵移动，或方向晚于一个 tick，幻想即失败。

承诺边界：

1. **拖动出死区即起**：内置 `VirtualJoystick.deadzone_ratio` 是唯一阈值；阈值内为防抖 ZERO，阈值外二元满速。
2. **松手即归零**：InputSystem 保证 release 后最迟下一 `MOVEMENT_COMMIT` 写 ZERO；角色实际停步由 PlayerController 保证，集成目标为 `p95 ≤ 50 ms`。
3. **精准是方向与时机**：MVP 不提供模拟慢速；analog/hysteresis 仅作为灰盒比较项，不进入当前公开契约。
4. **整 tick hitch 不是 selective skip**：若整个 physics tick 未运行，InputSystem 与 PlayerController 都不运行；恢复后的首个 tick 必须采最新 action 状态。系统不再定义“只跳过 InputSystem”的虚构路径。

## Detailed Rules

### Core Rules

> **UNARMED / preactive bootstrap invariant**：Host构造后默认`callbacks_armed=false`、`runtime_ingress_armed=false`且`shield_bank_service_enabled=false`。在任何battle input节点入树前，唯一GameRoot bootstrap必须恰调用一次`Input.set_use_accumulated_input(false)`并readback `Input.is_using_accumulated_input()==false`，同时只读验证`ProjectSettings.get_setting("input_devices/buffering/agile_event_flushing", false)==false`；随后在BOOT输入target尚未激活的无await区间恰调用一次`Input.flush_buffered_events()`丢弃/派发所有历史buffer。这里“项目effect=0”精确指项目Control callback、scene transition、choice/movement/gameplay effect均为0，不宣称Godot InputMap/cache/pressed状态零修改；BOOT该窗口项目Input polling与`window_input` consumer均为0，flush后四个movement action必须`pressed=false && raw=0`。本局后续Input setter、flush与ProjectSettings runtime mutation都必须为0，initialize及每次ACTIVE的`PRE_ACQUIRE`再次readback，漂移返回`INVALID_CONFIG`且不取得Viewport owner、不写gate。这样项目注入与正常OS事件不会先滞留Godot全局Input buffer再跨越Viewport gate。Host/shield/VJ可以已在树且为`PROCESS_MODE_ALWAYS`，但VJ必须不可命中新press；UNARMED及armed-IDLE期间，shield命中touch时执行`accept_event()`后走`PREACTIVE_DISCARD`，不得写gesture/bank/carrier/action或`pending_input_status`，跨ACTIVE仍held的该手势不得晋升，只有最终Viewport物理开放后的新OS press可建立generation。这里“零运行时mutation”只约束项目owned input runtime字段；允许并要求引擎Viewport更新handled/touch-focus。Host `_notification`在preactive期间不得写普通runtime latch，但允许写恰一个预分配、无需trusted tick的`preactive_invalidation_latched + reason_bits`；它只记录APP_BACKGROUND/INPUT_GEOMETRY_CHANGED并使VJ继续不可命中，不执行safe close或重建。`initialize`是主线程、无await/无用户callback的同步调用：保持UNARMED，最后一次读取当前geometry并完成全部验证，若Input accumulated或ProjectSettings agile readback不合法则`INVALID_CONFIG`，若preactive invalidation已latch则以`WRONG_STATE`安全中止；随后seed `safe_close_tick_revision`，创建并保存精确bound Callable、连接VJ signal，最后原子`callbacks_armed=true`并进入IDLE，但仍保持`runtime_ingress_armed=false`与`shield_bank_service_enabled=false`。任何failure都精确disconnect已连接Callable、保持UNARMED、bank为空且input不可达；无preactive invalidation的`publish_runtime_state(IDLE→ACTIVE)`仅原子置`runtime_ingress_armed=true`并保持shield service关闭，物理new-press route仍须等待GameRoot的Viewport `ACTIVATION_SUCCESS` release。

> preactive invalidation命中后initialize必须立即返回，禁止继续seed/connect/arm；只有latch为空的分支才可执行trusted tick seed及后续步骤。

1. **参与者与顺序**：InputSystem phase participant 在 BATTLE_LOADING 固定注册，允许 phase 为 `MOVEMENT_COMMIT` 与 `POST_DEFERRED_BARRIER`。其唯一 canonical row 为`INPUT_PHASE_ROW_V1={participant_id=INPUT,role_id=INPUT,stable_order=1,allowed_phases={MOVEMENT_COMMIT,POST_DEFERRED_BARRIER},allowed_success_statuses={OK},owner_contract_id=InputSystem/v1,owner_gdd_path=design/gdd/input-system.md,phase_row_id=INPUT_PHASE_ROW_V1,required=true}`；在 `MOVEMENT_COMMIT` 内必须先于 PlayerController；Active 后不可增删或重排。`OK_NOOP`不是Input participant success status，Input无业务字段贡献时仍必须返回`OK`并完成phase row exactly-once。
2. **驱动职责分离与callback ABI**：pausable 的 InputSystem phase participant 禁定义 `_process`/`_physics_process`，仅由 GameRoot `run_phase(phase, context, lease_id) -> int status` 驱动。唯一GameRoot集中编排节点精确使用`PROCESS_MODE_ALWAYS`，作为项目禁participant自主process规则的显式例外：其`_physics_process(delta: float) -> void`仅在SceneTree未暂停且GameRoot处于允许技术tick的状态时驱动七个physics phase；其`_process(delta: float) -> void`仅在`BATTLE_PAUSED/RESUME_PREPARING`驱动control pump，未暂停时不得重复驱动七phase。两个callback都必须先做顶层state/pause gate，不能双跑phase或把Paused误跑为gameplay phase。`VirtualJoystickHost` 是独立的 `Control`/GUI adapter，使用 `PROCESS_MODE_ALWAYS` 接收引擎 GUI event、lifecycle notification与内置节点signal，并唯一持有预创建typed `MovementIngressShield`；shield同样固定为`PROCESS_MODE_ALWAYS`，Host只维护其预分配held-touch bank与只读阻塞predicate。Godot 4.7.1的VJ信号精确为`pressed()`与`released(input_vector: Vector2)`，没有独立`canceled` signal；项目adapter固定为`_on_vj_pressed(callback_epoch: int) -> void`与`_on_vj_released(input_vector: Vector2, callback_epoch: int) -> void`，其中epoch由主线程direct `Callable.bind(epoch)`追加。Host保存同一`pressed_callable/released_callable`身份并在旧节点移出树前精确disconnect；shield入口固定为`_gui_input(event: InputEvent) -> void`，Host lifecycle入口固定为`_notification(what: int) -> void`。ScreenTouch canceled由shield `_gui_input`处理，或在已归属VJ时经引擎non-pressed路径最终触发`released`，不得伪造第三种VJ callback。`callbacks_armed=true`只表示普通signal/GUI callback可进入adapter，直至teardown才关闭；`runtime_ingress_armed=true`只允许ACTIVE下新的VJ press、generation与movement action/carrier路径；`shield_bank_service_enabled=true`只允许LOCK_PENDING/FROZEN/RESUME_LOCKED下shield按current-epoch FSM写bank、choice predicate与first-error latch。consumer closed时旧VJ current-epoch terminal仍可在`callbacks_armed=true`下清claim/pending release，但不得创建新generation或movement intent。preactive阶段两类service都为false，touch统一走PREACTIVE_DISCARD，lifecycle callback只允许写preactive invalidation latch；runtime ingress曾开放后，仅APP_BACKGROUND/geometry invalidation callback除普通字段外，允许对当前active node执行一次预冻结的`mouse_filter=MOUSE_FILTER_IGNORE`或经Godot 4.7.1验证的等价hit-route disable。普通pause不得把仍持有claim的VJ改为IGNORE，而由同步state/cancel路径关闭runtime ingress并打开shield service。Host/shield callback不执行safe close、不发布gameplay intent、不写actions/carrier、不推进GameRoot/Input顶层状态；GameRoot paused control pump在引擎恢复派发main-loop后的最迟下一iteration调用typed `service_pending_input_fault`消费异步failure。
3. **固定输入架构**：MVP 使用 Godot 4.7.1 内置 `VirtualJoystick`、`JOYSTICK_DYNAMIC`、`VISIBILITY_WHEN_TOUCHED` 和四个预声明 `StringName` action；不再保留“内置或自定义”双轨实现。稳定 API 边界上 Host 恰有一个在树、已连接的registered active VirtualJoystick与恰一个预创建、在树、typed `MovementIngressShield`。`shield_bank_capacity=max(manifest.max_concurrent_touches)`，其中max遍历本artifact全部支持Android/iOS设备的冻结`SupportedTouchEventOrderingManifest`且结果必须为正；bank按并发entry定容，以固定槽查找任意非负、可稀疏的`touch_index`，禁止以index直接寻址或运行时扩容。shield初始化只验证可内省事实：owner identity、Host/shield/registered VJ的精确process mode、默认effective closed、完整movement rect覆盖、位于交互UI下/VJ上、ancestor递归mouse/process均启用、consumer-closed时`get_mouse_filter_with_override()==MOUSE_FILTER_STOP`、ACTIVE时effective filter为IGNORE及bank容量；任一不满足返回`INVALID_CONFIG`且input不开放。`accept_event()`不属于可内省初始化属性，改由静态call-site与行为AC证明。只有`shield_bank_service_enabled=true`且state∈`{LOCK_PENDING,FROZEN,RESUME_LOCKED}`时才按Shield Bank FSM消费movement touch：新的current-epoch非负index press占用一个FREE槽并成为HELD；同一`{shield_epoch,touch_index}` duplicate press只消费并计诊断，不新增entry、不刷新epoch；matching release或`InputEventScreenTouch.is_canceled()`恰释放一次；duplicate/unknown/stale terminal只计诊断；terminal后新的press才可重新占用。UNARMED/armed-IDLE是明确例外：shield service=false，只PREACTIVE_DISCARD且bank始终空。capacity已满、负index或本地FSM非法边只由shield-service callback写`INVALID_ARGUMENT` first-error-wins latch、调用`accept_event()`并保持shield/consumer closed，safe close仅由随后同步Public API执行。跨epoch反序等callback不可辨识的平台违例不要求伪检测，只由`SupportedTouchEventOrderingManifest`与真机trace判FAIL。shield存在held touch时保持effective STOP以接收其motion/terminal且`is_choice_input_blocked()==true`；全部matching terminal后才允许撤shield并等待fresh OS press。已有VJ touch-focus的release/cancel仍直达保持`PROCESS_MODE_ALWAYS`且非IGNORE的旧VJ；Godot 4.7.1将canceled ScreenTouch作为非pressed分支触发VJ release/reset。rebuild内部registered VJ允许短暂为0，但旧、新节点不得同时对new press可达。普通暂停保留VJ及shield epoch直到matching terminal；APP_BACKGROUND或safe geometry invalidation不等待缺失terminal，consumer-closed rebuild同时checked推进VJ `gesture_epoch`与`shield_epoch`并清空旧epoch held bank，旧epoch迟到事件只计诊断；完成preflight后仍只接受fresh OS press。
4. **唯一 deadzone**：`VirtualJoystick.deadzone_ratio=0.15`（provisional tuning）；四个 InputMap action deadzone 固定为 `0.0`，InputSystem 调 `Input.get_vector(..., 0.0)`，禁止再次判 px deadzone。
5. **二元输出**：action vector 先做finite守卫；ZERO输出ZERO，非ZERO按F1 scale-first安全归一化，幅值只允许`{0,1}`，不增加epsilon deadzone。
6. **carrier 单向数据流**：GameRoot 在 BATTLE_LOADING 预分配 `MovementIntentCarrier`；InputSystem 写、PlayerController 只读。禁止用 Dictionary、带参 signal 或方法字符串传递 movement intent。
7. **移动 claim**：内置 VirtualJoystick 管理当前 movement touch；Host 只跟踪公开 `pressed/released` signal、`claim_active`、gesture gate、generation 与 `gesture_epoch`，不读取引擎私有 `touch_index`。第二触点不得自动晋升；普通路径必须观察release/cancel对应的公开`released`后重新 press。release latch必须记录`{gesture_epoch,press_generation}`而非单个bool；同一physics tick前更新generation的fresh press优先于旧generation release。只有 APP_BACKGROUND 或 safe geometry invalidation 的显式节点重建可替代缺失/已被引擎静默reset的旧 terminal；支持artifact若既不派发可观察cancel/released、也不产生可重建lifecycle边界，则不得进入implementation-ready。
8. **pause barrier 取消**：GameRoot latch pause intent 后，在 `POST_DEFERRED_BARRIER` 先调用 `cancel_input`；只有返回 `OK` 才可继续 `SpatialGrid.request_pause`。direct pause 与 `PAUSE_PENDING` drain 走同一协议，其他 status 经 matching phase cleanup 后进入 CONTROLLED_FAULT。
9. **锁定区间**：`PAUSE_PENDING/BATTLE_PAUSED/RESUME_PREPARING`、BATTLE_ENDING、CONTROLLED_FAULT及APP_BACKGROUND/INPUT_GEOMETRY_CHANGED pause reason均禁止产生新movement intent。

> Core Rule 10及后文未另行限定的“consumer closed时new press进入shield bank”只指runtime ingress曾开放后的LOCK_PENDING/FROZEN/RESUME_LOCKED；UNARMED/armed-IDLE始终按PREACTIVE_DISCARD且不形成held。Active中的退出请求必须先由GameRoot置`manual_exit_pending=true`并走同一`MANUAL`安全暂停；破坏性的退出确认只允许在`BATTLE_PAUSED`、consumer closed且两类held predicate clean时接受。Input只负责对应UI触点的现有fresh-press/terminal约束，不得从ACTIVE直接触发teardown或Save。

`cancel_input`是consumer-close操作，不是终止操作：它只负责按当前state提交`LOCK_PENDING/FROZEN/RESUME_LOCKED`安全边界、清理action/carrier并保留旧claim的terminal责任；它不得直接写`TERMINATED`。只有同一owner的`teardown`才提交`TERMINATED=false/false/false`，随后执行disconnect/remove/queue_free。历史文字中的“cancel then terminal”均解释为“cancel成功后由GameRoot进入teardown”，不得实现为cancel自身的隐式terminal迁移。

10. **fresh press、resume intent、background revision 与held drain**：普通 cancel 时仍 held 的旧 movement claim 进入 ignored-until-terminal；consumer closed期间movement rect中的new press由shield消费并成为shield-held touch，永不到达VJ/gesture FSM。GameRoot仅在旧VJ claim与shield-held bank都为空时才可开始resume。`resume_requested_latched`是唯一幂等bool，不计数、不排队：choice-only在全部blocking choice提交完成且无`MANUAL/APP_BACKGROUND` reason时置true；manual pause只在合法Continue被接受后置true；始终foreground的`INPUT_GEOMETRY_CHANGED`在reconfigure preflight、Grid pause/quarantine与FROZEN publish均成功且无blocking choice/MANUAL/APP_BACKGROUND残留时自动置true；geometry与choice重叠时等待preflight与全部choice完成后自动置true。GameRoot另持有checked monotonic `background_readiness_required_revision`与`background_readiness_acked_revision`：每个新的APP_BACKGROUND revision将required推进到最新值并立即使readiness gate未满足，duplicate同revision不推进；多个尚未确认的background可coalesce为最新revision。任意组合仍有`APP_BACKGROUND`时，foreground preflight/FROZEN/choice完成后仍保持Paused，合法readiness/Continue只确认当时最新required revision并令acked追平required；任意组合仍有`MANUAL`也必须等待Continue，MANUAL与APP_BACKGROUND重叠由同一个合法Continue同时满足manual intent与当时最新background revision，不叠加两次确认。background与geometry合并时background hold优先。`can_start_resume`必须同时满足`resume_requested_latched=true`、`background_readiness_acked_revision==background_readiness_required_revision`及held predicate clean；因此Continue后、ACTIVE publish前到达的新background revision即使保留generic resume latch也必须重新等待一次确认。readiness/Continue press只产生resume intent/ack，不得建立movement generation；ACTIVE后仍要求新的OS movement press。duplicate/coalesced reason不累计intent、不重复choice effect。generic latch只有ACTIVE publish成功、battle ending或fault cleanup才清除，不可逆点前的合法held或invalidation rollback必须保留；background ack不得跨越更新的required revision。每个resume attempt只捕获一次`attempt_input_rebuild_revision/attempt_background_revision/attempt_geometry_snapshot`；prepare、arm、swap、Grid/Pool/authority三次matching publish的相邻checkpoint之间、三次publish后、lease/quarantine cleanup后、每个held-drain iteration及最终ACTIVE尾段都必须比较当前revision/invalidation与该快照，pending Input fault与held检查不能替代。resume开始后、首次Grid publish前若出现shield-held touch，须abort未发布candidate、matching close lease、发布`RESUME_LOCKED→FROZEN`并回Paused等待terminal，不视为failure；matching release/cancel且pending fault service=OK后，只要完整`can_start_resume`为true且无resume transaction在途，paused pump必须自动且恰启动一次新resume attempt，不要求第二次Continue、不重复提交choice effect。连续提前press可重复安全rollback，但始终只有一个latched intent与一个在途attempt。不可逆点后出现held touch且无revision/invalidation变化时，须完成matching publish与所有lease/quarantine cleanup，保持SceneTree paused、consumer closed且state=`RESUME_LOCKED`，在无open lease的`RESUME_HELD_DRAIN`尾段等待bank清空；若不可逆点后出现新的input/background revision或invalidation latch，则仍完成正确tx的matching publish与全部cleanup，但必须保持`foreground_input_blocked=true`并进入fault，禁止清block、进入/继续held drain或发布ACTIVE。最终尾段只有在`required==acked==attempt_background_revision`、`input_rebuild_revision==attempt_input_rebuild_revision`、无新invalidation/pending fault且held为空时才可原子发布ACTIVE，不重跑Grid/Pool resume。随后必须观察新的OS `pressed`才建立generation，旧VJ或shield触点的motion/terminal都不得自动晋升为movement。cancel时无旧claim且shield bank为空则直接处于`WAIT_FRESH_PRESS`，不要求虚构terminal。选择UI中的press仍按choice gate处理；它由上层UI拥有touch focus，不登记为shield-held touch；其matching terminal ownership由IG-IS3关闭，未关闭前不得宣称integration-ready。

> **Root Window physical gate + ACTIVE activation guard（权威阶段矩阵）**：所有`IDLE/RESUME_LOCKED→ACTIVE`都由唯一GameRoot管理persistent root Window；该Window同时承载Stage Camera与Host/Shield/VJ/BattleUI，MVP不创建逐局SubViewport。概念阶段固定为`PRE_ACQUIRE→SET_TRUE_IN_FLIGHT→GATE_HELD→reasoned release`。loading全过程固定`callbacks_armed=true、runtime_ingress_armed=false、shield_bank_service_enabled=false`，因此touch只走PREACTIVE_DISCARD；resume全过程直到ACTIVE局部提交固定`callbacks_armed=true、runtime_ingress_armed=false、shield_bank_service_enabled=true`，因此consumer-closed ScreenTouch可由shield FSM登记/清除bank，但不能进入VJ或movement路径。`PRE_ACQUIRE`先验证Input accumulated实时readback与ProjectSettings agile冻结值均false、root Window及Host/Shield/VJ identity、`gui_disable_input=false`且`viewport_input_gate_owned=false`；任一失败不取得owner、不调用setter。验证通过后checked置owner sentinel并调用`set_disable_input(true)`；setter-in-flight只允许既有typed latch/diagnostic或shield containment。true返回/readback后才进入`GATE_HELD`并保证Window/Control/VJ零投递。GameRoot执行service/revision/held observer，clean才`set_pause(false)`；返回后再显式observer，不依赖pause notification。两次observerclean才发布Input ACTIVE与GameRoot ACTIVE，最后`release_viewport_input_gate(ACTIVATION_SUCCESS)`调用false；false返回是物理route唯一0→1点。held-only先repause并reasoned release回drain；failure保持gate至battle input child detach且Home/Fault UI成为唯一target。项目静态审计要求GameRoot外root Window setter writer=0，并禁止activation callback直接注入InputEvent；完整同步重入矩阵以GameRoot R7/GATE-OQ-VIEWPORT为唯一权威。

> **第十轮GameRoot传播（中央权威，不复制事务内部）**：`resume_requested_latched`与`Grid→Pool→authority`事务规则不变。cleanup开始后old Host/Shield/VJ预期detach不再按BattleViewportTopologyManifest判drift；Input先terminal并撤销callback/latch写权，只为`CleanupViewportHandoffManifest`提供detached/read-only后置条件。gate已持有时`REUSED`且不得重复setter；未持有时由GameRoot最多重试3次。连续3次acquire/readback失败进入`ACQUIRE_FAILED_SAFE`，Input callback/writer与新input target均为0，destination只能是`SAFE_TERMINAL_NONINTERACTIVE`且要求重启；不得伪造release或自动返回可交互页面。InputSystem不拥有attempt/count、ActivationCommitJournal或Viewport gate。

> **第十轮GameRoot传播**：GameRoot的ALWAYS `_process`包含互斥的Paused/Resume control pump与无gameplay effect lifecycle pump。后者的资格由`ActivationCommitJournal/CleanupSubstate尚未terminal`决定，不限于旧TopState，因此top-state checkpoint完成后仍可推进。normal destination先`STAGED_NONINTERACTIVE`，逐checkpoint满足expose-or-NA、top-state、ACTIVE、release；retryable Loading使用`ExposureRequirement.NOT_APPLICABLE`。连续三次gate失败固定为`SAFE_TERMINAL_NONINTERACTIVE`且release=0。Input只提供terminal/callback清零后置条件，不拥有CleanupSubstate、ActivationCommitJournal、DestinationUIState或激活manifest。

> Host的signal、`_gui_input`、`_notification`与其他引擎虚回调必须逐项登记在GameRoot `GameplayCallbackAllowlist`。回调只可写allowlist明列的control/invalidation/diagnostic latch；`NOTIFICATION_PAUSED/UNPAUSED`不得直接写movement、action、carrier、phase、顶层state或resume intent。GameRoot在preflight、每个ACTIVE physics tick前与resume checkpoints readback `Engine.physics_ticks_per_second==60`、`Engine.time_scale==1.0`及冻结Viewport topology；Input只消费通过门控后的调用。
11. **唯一移动输入源**：四个 movement action 在生产 InputMap 中必须存在、互异、deadzone=0 且 `action_get_events(action).is_empty()`；生产设置 `input_devices/pointing/emulate_touch_from_mouse=false`。除内置 VirtualJoystick 的原生 action writer 与 InputSystem 私有 `release_movement_actions_and_clear` helper 外，项目 GDScript 不得对四 action 调用 `Input.action_press/release`；Host rebuild不得另写 actions。原始键盘、原始鼠标和gamepad不得改变movement carrier；mapped gamepad/keyboard只允许命中八行Meta UI action并由presenter生成typed UI command。直接注入的合法 `InputEventScreenTouch` 与真实 touch 使用同一引擎路径，属于有效输入，不虚构 device/synthetic filter。
12. **单拇指 UX 与坐标 owner**：Dynamic 起按区为转换到 Host local Canvas 坐标后的interactive safe viewport下方45%，排除HUD、暂停按钮、活动bottom sheet与尚未被display safe area覆盖的system navigation gesture inset；左右手均可在不换握、不借助另一只手的条件下完成移动与选择。`SafeViewportGeometryProvider` 是 `display physical → window client physical → viewport logical → Host local Canvas` 转换及`residual_navigation_gesture_insets`的唯一owner；每个支持artifact须由冻结平台manifest证明inset已包含于display safe area（此时residual为0）或提供四边非负physical inset再走同一变换，禁止默认safe area自动覆盖系统手势区或跳过viewport stretch/final transform。
13. **项目自有热路径禁已知分配构造**：范围为 InputSystem GDScript 的 action polling、normalization、carrier write 与普通 pause cancel；静态守卫只证明显式 denylist 未出现，不宣称证明引擎 C++、operator 或 native call 零分配。APP_BACKGROUND/geometry invalidation节点重建是非稳态lifecycle例外，须在gameplay重新开放前完成。
14. **无 hover**：所有交互仅由 touch press/drag/release/cancel 驱动，不设计 hover 状态。
15. **状态与物理gate单一 owner**：GameRoot 是 Input 顶层状态与persistent root Window `gui_disable_input`的唯一owner，通过 `publish_runtime_state(next_state,tick_revision)` 显式发布合法Input迁移；InputSystem/Host不从phase、SceneTree pause或signal隐式推断顶层状态，也不得写Viewport gate。runtime曾开放的ACTIVE进入consumer closed时，Input在完成argument/tick/state/reason验证后必须先执行唯一私有`commit_consumer_closed()`：在一个无函数调用、无property setter、无signal、无Callable、无`await`的主线程局部提交中同时置Input state=`LOCK_PENDING`、`runtime_ingress_armed=false`、`shield_bank_service_enabled=true`并保持`callbacks_armed=true`；只有完整`LOCK_PENDING=true/false/true`已发布后，才把shield effective filter设为STOP并执行可能失败的action/carrier clear。Godot setter同步notification/signal因此只能观察完整locked tuple；`ACTION_CLEAR_FAILED`也保持该tuple进入fault cleanup。已处于LOCK_PENDING/FROZEN/RESUME_LOCKED时不迁移且保持`true/false/true`后再执行STOP/clear；IDLE ending/fault cleanup保持`true/false/false`与PREACTIVE_DISCARD，绝不调用`commit_consumer_closed()`或开启bank service。进入ACTIVE前必须验证旧VJ claim与shield-held bank均为空、caller已独占root Window且`gui_disable_input=true`。Input ACTIVE publish只在`GATE_HELD`中切换VJ/shield filter、观察activation guard并以单一局部提交置Input state=ACTIVE、`runtime_ingress_armed=true`、`shield_bank_service_enabled=false`，返回OK时物理event仍不可投递；GameRoot随后提交自身ACTIVE字段，只有`release_viewport_input_gate(ACTIVATION_SUCCESS)`的false setter返回才开放物理route。held-touch未终止时ACTIVE publish返回`WRONG_STATE`且零开放，GameRoot必须按Core Rule 10先完成合法held-drain，不能把正常玩家press导致的该状态当technical fault。publish OK后至Viewport开放前注入事件必须被Viewport丢弃；Viewport开放返回后至首个MOVEMENT_COMMIT前的第一下新OS press必须可接受。teardown先以同类callback不可观察的单一局部提交置Input state=`TERMINATED`并同时关闭callbacks、runtime ingress与shield service，清空bank/choice/pending latch写权；随后才执行filter setter、disconnect、remove_child与queue_free，迟到callback只能追加suppressed diagnostic。IDLE从未开启shield service。
16. **节点几何不可变与替换**：active VirtualJoystick 从进入树到移出树期间不得调用会触发引擎私有 reset 的 size/tip/offset setter，也不得因 bottom sheet 修改 Control geometry。candidate 必须离树按固定顺序完成四action、mode/theme、size/tip/offset与几何配置并validate，且从构造到进树登记完成前保持`MOUSE_FILTER_IGNORE`。APP_BACKGROUND/geometry replacement时旧节点先`MOUSE_FILTER_IGNORE`、断signal、`remove_child`，再登记new identity/epoch/signal并入树，旧节点随后`queue_free`。consumer closed时candidate保持IGNORE且shield enabled；后续`publish_runtime_state(ACTIVE,...)`只准备Control topology/runtime ingress，外部物理new-press route仍为0，直到GameRoot完成`ACTIVATION_SUCCESS` release后才为1。普通pause不替换节点、不改claimed VJ filter，只启shield。bottom sheet以更高 CanvasLayer/稳定 scene-tree 顺序、`MOUSE_FILTER_STOP`与`accept_event()`拦截选择区域new press，不resize已claim节点。

### States and Transitions

| Input state | GameRoot state/reason | Entry action | Behavior / Exit |
|---|---|---|---|
| `IDLE` | BOOT/HOME/PREP/BATTLE_LOADING 未开放 input | carrier 预分配并 clear；`callbacks_armed=true`、`runtime_ingress_armed=false`、`shield_bank_service_enabled=false` | VJ不可命中；shield touch走PREACTIVE_DISCARD且不登记bank/gesture；preactive invalidation保持latch；GameRoot仅在latch为空时发布 `IDLE→ACTIVE` |
| `ACTIVE` | BATTLE_ACTIVE | `runtime_ingress_armed=true`、`shield_bank_service_enabled=false`；fresh press gate 已开放或等待新 press | MOVEMENT_COMMIT 采 action vector并写 carrier；pause/fatal close先原子提交`ACTIVE→LOCK_PENDING + true/false/true`，再设shield STOP并clear |
| `LOCK_PENDING` | pause intent latched / PAUSE_PENDING | barrier 内 `cancel_input`；`runtime_ingress_armed=false`、`shield_bank_service_enabled=true` | carrier清零、action释放、拒绝新movement intent；旧VJ terminal仍可清claim，shield FSM持有new press；BATTLE_PAUSED → FROZEN |
| `FROZEN` | BATTLE_PAUSED | GameRoot 在显示pause/choice UI前发布；runtime ingress保持false、shield service保持true，choice gate按旧VJ/shield-held claim决定 | UI 可处理被choice gate允许的新press；两类claim均空后GameRoot才可进入RESUME_PREPARING并发布`FROZEN→RESUME_LOCKED` |
| `RESUME_LOCKED` | RESUME_PREPARING / RESUME_HELD_DRAIN / Viewport-gated两阶段ACTIVE提交 | runtime ingress保持false、shield service保持true；resume transaction 前再次 cancel；已有background/geometry revision时在开lease前完成host rebuild | 首次matching publish前的新invalidation或shield-held touch完成clean abort/close后发布`RESUME_LOCKED→FROZEN`；不可逆点后invalidation按GameRoot收敛/fault，合法shield-held touch则完成publish/cleanup后无lease等待terminal；held清空后GameRoot先取得Viewport物理gate并复核，再在Input仍locked时unpause并复核，随后由activation guard原子关闭shield service/开启runtime ingress并提交Input ACTIVE；GameRoot字段提交后以Viewport gate false唯一开放，全部成功后仍须fresh press |
| `TERMINATED` | BATTLE_ENDING / CONTROLLED_FAULT / teardown | 先原子提交state与三字段为`TERMINATED + false/false/false`并撤销bank/latch写权，再执行route/node/adapter cleanup | 本实例不可恢复；新battle创建新实例并initialize为IDLE |

APP_BACKGROUND 与 `INPUT_GEOMETRY_CHANGED` 是 GameRoot pause reason，不是 InputSystem 顶层状态；两者走 `ACTIVE → LOCK_PENDING → FROZEN/TERMINATED`。foreground/reconfigure preflight 完成host rebuild前不得发布ACTIVE。InputSystem 不反向改变GameRoot状态；所有合法迁移与调用时点以Public API矩阵为准。

`publish_runtime_state`只允许`IDLE→ACTIVE`、`LOCK_PENDING→FROZEN`、`FROZEN→RESUME_LOCKED`、`RESUME_LOCKED→ACTIVE`，以及专用resume-abort边`RESUME_LOCKED→FROZEN`；`ACTIVE→LOCK_PENDING`只能由已通过前置验证的`cancel_input`或pending-first `ASYNC_SAFE_CLOSE`通过唯一`commit_consumer_closed()`完成，close commit一旦发布即使后续action clear返回`ACTION_CLEAR_FAILED`也不得回到ACTIVE。任意非TERMINATED状态→TERMINATED只能由`teardown`完成。`IDLE→ACTIVE`只有在preactive invalidation latch为空、VJ claim与shield bank均为空、carrier/actions clean，GameRoot已独占正确Viewport、验证`gui_disable_input=true`，且Input accumulated实时readback与ProjectSettings agile冻结值均为false时合法；Input在该物理gate下完成filter guard并局部提交state/runtime ingress，返回OK仍不开放物理事件。GameRoot随后提交BATTLE_ACTIVE/consumer字段并通过`release_viewport_input_gate(ACTIVATION_SUCCESS)`唯一开放；合法加载期早按因PREACTIVE_DISCARD不形成held，不能使该publish失败。若buffering配置漂移，必须在`PRE_ACQUIRE`以`INVALID_CONFIG`失败且Viewport setter调用数=0；若preactive invalidation或activation guard已latch则返回`WRONG_STATE`且零Input提交/零Viewport开放，GameRoot将typed preactive cause识别为BATTLE_LOADING lifecycle abort而非technical fault，逆序cleanup；只有已经取得的gate才按release reason恢复。`RESUME_LOCKED→FROZEN`只在首次Grid/Pool matching publish这个不可逆点之前、consumer/ingress closed、Grid/Pool candidate已abort、所有resume lease已matching close、carrier为ZERO、四action均`pressed=false && raw=0`且shield enabled时合法；不可逆点后调用必须返回`WRONG_STATE`且不得回滚。返回OK后choice gate同时按旧VJ claim与shield-held bank决定，movement ingress仍closed。不可逆点后的`RESUME_HELD_DRAIN`不是新Input顶层状态：Input仍为RESUME_LOCKED，且Grid/Pool candidate、lease、quarantine都已清理；bank清空前不得调用ACTIVE publish。TERMINATED不可在同一实例恢复；新battle使用新InputSystem/Host实例并重新initialize。

### Gesture Gate FSM

| Gate state | Event | Action | Next |
|---|---|---|---|
| `WAIT_FRESH_PRESS` | current-epoch `pressed` 且 Input state=`ACTIVE` | checked increment generation；记录 `claim_active=true`；若存在较旧generation的pending release则标记superseded | `TRACKING` |
| `WAIT_FRESH_PRESS` | `pressed` 且 Input state非 `ACTIVE` | 标记 claim ignored，不开放 gameplay gate | `WAIT_IGNORED_RELEASE` |
| `TRACKING` | current-epoch `released` | `claim_active=false`、记录`pending_release={gesture_epoch,press_generation}`；只更新gesture state，不写carrier | `WAIT_FRESH_PRESS` |
| `TRACKING` | normal `cancel_input` 且 claim held | action release + carrier clear；generation置 `-1` | `WAIT_IGNORED_RELEASE` |
| `TRACKING` | normal `cancel_input` 且无 claim | action release + carrier clear；generation置 `-1` | `WAIT_FRESH_PRESS` |
| `WAIT_IGNORED_RELEASE` | current-epoch `released` | `claim_active=false`、choice gate解除；该release本身不产生choice/movement intent | `WAIT_FRESH_PRESS` |
| 任意 | stale-epoch signal、duplicate pressed、无 claim release | 忽略并计诊断；不改 carrier | 原状态 |
| 任意 | 新`input_rebuild_revision`的Host rebuild success | checked计算next epoch并离树预建candidate；validate通过后old node不可命中/断signal/移出树，再原子登记epoch/revision、解除旧claim/choice block并清除pending release；新节点在consumer closed时仍不可命中 | `WAIT_FRESH_PRESS` |

`generation_counter`初值为`0`，首次accepted press checked increment后发布generation=`1`；`gesture_epoch`初值为`1`。两者都是signed 64-bit checked monotonic counter，公开generation/epoch始终为正，carrier未活动时generation固定`-1`。GUI signal callback无返回通道：它只能写预分配的gesture/shield-bank fields、`pending_release_epoch/pending_release_generation`、只读choice gate与first-error-wins `pending_input_status`，绝不写carrier/actions或迁移顶层状态。generation increment失败时不得接受press；下一次GameRoot同步API先观察latch并经InputSystem私有helper完整release当前dirty action、clear carrier后返回精确status，PlayerController不能先消费。合法`run_phase/cancel_input/service_pending_input_fault/teardown`消费pending release时：若当前无claim，或pending的`{epoch,generation}`仍是最新accepted generation，则同步clear；若同epoch已有更大generation的active fresh press，则丢弃旧pending并在MOVEMENT_COMMIT采样当前action，不得清掉新手势；跨epoch pending仅计stale诊断并丢弃。Host rebuild失败由同步`ensure_rebuilt_after_invalidation`直接返回；不复用旧geometry并进入ControlledGameplayFault。GameRoot为APP_BACKGROUND或safe geometry invalidation分配新的正`input_rebuild_revision`；Host记录`last_rebuilt_revision`，同revision只有在`geometry_fingerprint`与完整canonical geometry field bits都相等时重复ensure才返回无副作用OK，较旧revision、fingerprint不同或任一canonical字段不同均返回`STALE_TICK`。GameRoot将同一process frame内多个invalidation coalesce为最新revision/snapshot，每帧最多发起一次新revision rebuild commit，较旧revision只计诊断而不构造candidate。普通pause的choice gate与movement gate分离：只有旧VJ movement claim与shield-held bank都为空时，pause UI的下一次新press才可选择；任一非空时`is_choice_input_blocked()`保持true直到current-epoch matching release/cancel，movement rect的其他new press始终由shield消费。

### Shield Bank FSM

本FSM只在`callbacks_armed=true && shield_bank_service_enabled=true && runtime_ingress_armed=false`且Input state∈`{LOCK_PENDING,FROZEN,RESUME_LOCKED}`时启用；preactive IDLE的shield service=false，touch不查找/占用slot，也不更新epoch或诊断counter。ACTIVE的runtime ingress=true、shield service=false，new movement press只走VJ；TERMINATED三者均false。

每个预分配slot仅有`FREE/HELD`两态；key为`{shield_epoch,touch_index}`，slot释放后可被任意新的稀疏index复用：

| Slot/key state | Event | Callback action | Result |
|---|---|---|---|
| key不存在且有FREE slot | current-epoch、非负index `pressed` | 占用恰一个slot，写key并`accept_event()` | `HELD`，bank count +1 |
| matching key已`HELD` | duplicate `pressed`或motion | 只消费并计duplicate诊断，不写latch、不新增slot、不刷新epoch | 保持`HELD`，count不变 |
| matching key已`HELD` | `released`或`canceled=true` | 清key、释放恰一个slot并消费event | `FREE`，bank count -1 |
| key不存在 | release/cancel/motion或stale-epoch terminal | 只消费并计unknown/stale诊断 | bank不变 |
| key不存在且无FREE slot | 新的合法press | `INVALID_ARGUMENT` first-error-wins latch + `accept_event()` | bank不变、consumer保持closed |
| 任意 | 负index press或本地状态不变量破坏 | `INVALID_ARGUMENT` first-error-wins latch + `accept_event()` | bank不变、consumer保持closed |

同一index在matching terminal后可作为新的current-epoch press重新占用任意FREE slot。callback可判定的fatal集合仅为负index、capacity overflow与本地FSM不变量破坏；跨epoch same-index旧terminal晚到等身份不可辨识顺序不进入该集合，只由平台manifest/trace gate裁决。

### Runtime Contracts

> 本文件后续出现的“同revision + fingerprint + canonical geometry fields”均为简写，权威含义固定为：`geometry_revision`与`input_rebuild_revision`二元版本组匹配，geometry与instance-frozen candidate-config两个fingerprint均相等，且两组完整canonical fields逐项exact equality；任何旧句不得被解释为只比较geometry或只比较单一revision。

- **MOVEMENT_COMMIT**：InputSystem 先写 carrier，PlayerController 后读；同 tick 顺序由 GameRoot 固定注册表保证。
- **POST_DEFERRED_BARRIER**：若 `context.pause_intent_latched=true`，InputSystem 执行 `cancel_input(context.pause_reason, context.tick_revision)`；返回 `OK` 后 GameRoot 才能调用 Grid pause并进入 PAUSE_PENDING/BATTLE_PAUSED。
- **显式状态发布**：BATTLE_LOADING完成全部preflight后，GameRoot先在`PRE_ACQUIRE`验证Input accumulated实时readback与ProjectSettings agile冻结值均为false，以及Viewport identity/owner/gate，验证成功才进入`SET_TRUE_IN_FLIGHT`；true setter返回/readback=true后进入`GATE_HELD`，复核clean才以activation guard发布`IDLE→ACTIVE`。Input返回OK后GameRoot提交BATTLE_ACTIVE/consumer字段，最后以`release_viewport_input_gate(ACTIVATION_SUCCESS)`恢复Viewport input。pause cancel成功即由InputSystem进入LOCK_PENDING；Grid pause+quarantine成功后、pause UI开放前由GameRoot发布FROZEN；RESUME_PREPARING开始且无open lease时发布RESUME_LOCKED；resume三次publish与cleanup完成、consumer仍closed且两类held state均空时，GameRoot按同一阶段矩阵取得Viewport gate，再保持Input locked调用`SceneTree.set_pause(false)`；setter返回后由GameRoot显式执行第二次复核，随后以activation guard发布Input ACTIVE。返回OK后才清foreground block/提交GameRoot ACTIVE，并以成功release作为唯一物理开放点。ending/fault/partial-loading cleanup在任何old child detach前执行GameRoot `CLEANUP_PRE_ACQUIRE`：既有owner复用为`REUSED`，未持有且验证成功为`ACQUIRED`，失败为`ACQUIRE_FAILED_SAFE`并禁止旧Input route/callback写；只有destination tuple与唯一Home/Prep/Fault/Settlement UI target、旧Input terminal/detach、pause-off均满足后，才以`LOAD_ABORT_OR_FAULT_CLEANUP`释放。任一publish非OK不得开放后续consumer/UI；由正常shield press形成的held state必须先走确定性drain，不得直接调用ACTIVE再把`WRONG_STATE`当fault。
- **第十轮cleanup覆盖条款**：上行关于“首次acquire失败即ACQUIRE_FAILED_SAFE”与“唯一target满足即release”的旧句失效；权威顺序改为最多3次gate attempt，并由ActivationCommitJournal逐点完成expose-or-NA、top-state、ACTIVE-or-safe与release-or-NA。连续3次失败只能进入`SAFE_TERMINAL_NONINTERACTIVE`且release=0。
- **RESUME_PREPARING**：GameRoot在Grid/Pool resume transaction前先调用`service_pending_input_fault`并确认OK，再确认`is_choice_input_blocked()==false`且background required/acked相等，随后只捕获一次attempt input/background revision与geometry snapshot、发布RESUME_LOCKED并调用`cancel_input(RESUME_PREPARING,tick_revision)`；若有APP_BACKGROUND或safe geometry invalidation，还须以attempt快照调用`VirtualJoystickHost.ensure_rebuilt_after_invalidation`，当前revision只有在fingerprint与完整canonical geometry bits均已由preflight验证相等时才为无副作用OK。首次Grid publish是不可逆点：此前到达新invalidation时，固定执行`调用state-aware cancel_input(APP_BACKGROUND或INPUT_GEOMETRY_CHANGED)保持合法locked tuple并验证actions/carrier/pending release clean → 恢复旧owner引用 → abort每个candidate并matching close lease → Input仍FROZEN则不publish，已RESUME_LOCKED则publish_runtime_state(FROZEN)`，禁止在cancel前由外部另写runtime/service；随后回Paused做preflight。若第二次cancel/clean非OK，禁止正常rollback/FROZEN publish，但GameRoot必须保存其root status并执行`恢复old owner→fault-abort未publish candidate→matching close lease→清staging/quarantine→Input/Grid/Pool teardown`的emergency cleanup。此前出现shield-held touch时不重复Input cancel，恢复old owner、fault-free abort candidate、matching close lease并发布FROZEN，保持Paused等待terminal且保留已有唯一`resume_requested_latched`；只有该latch已true时，terminal后才由paused pump自动启动恰一个new attempt，不重复choice effect。不可逆点之后到达invalidation时禁止回滚FROZEN；GameRoot须完成matching publish/lease/quarantine cleanup、保持shield与consumer closed并进入`CONTROLLED_FAULT` teardown，不发布ACTIVE。不可逆点后出现shield-held touch且attempt revision/invalidation未变化时不是failure：先完成matching publish、end lease与quarantine cleanup，转入无open lease的`RESUME_HELD_DRAIN`；每次paused control iteration先service pending fault，再比较attempt revision/invalidation并检查两类held state。held清空后进入Viewport-gated激活：GameRoot保持RESUME_PREPARING/Input RESUME_LOCKED与foreground block，先独占root Window并设`gui_disable_input=true`，同步focus/leave callback返回后复核；clean才调用`SceneTree.set_pause(false)`，调用返回后由GameRoot显式执行第二次service/revision/held复核；通过后才在Viewport disabled下调用guarded ACTIVE publish。guard failure恢复closed route并返回`WRONG_STATE`，GameRoot重新pause、保持Viewport gate与foreground block并fault；成功后GameRoot局部提交BATTLE_ACTIVE/consumer，最后以`gui_disable_input=false`唯一开放，不重跑Grid/Pool resume。
  - **激活尾段覆盖**：上行最后三句只表示阶段关系，权威执行顺序固定为`PRE_ACQUIRE(buffering=false/identity/owner/gate validation)→SET_TRUE_IN_FLIGHT(owner acquire + true setter callbacks while bool may remain false；合法ScreenTouch由shield containment)→true return/readback→GATE_HELD→service/revision/invalidation/held复核→held则reasoned release回drain / clean则set_pause(false)→setter返回→GameRoot显式再次复核→guarded Input ACTIVE publish→GameRoot local ACTIVE/block/latch/feedback commit→release(ACTIVATION_SUCCESS)→false return/clear owner`。`PRE_ACQUIRE` failure不得写Viewport；`SET_TRUE_IN_FLIGHT`只要求VJ/gameplay effect=0，允许loading PREACTIVE_DISCARD或resume shield bank containment；只有`GATE_HELD`要求Viewport delivery=0。已持gate的failure不得越过fault cleanup release，未持gate的failure不得伪造release。
- **Action names**：四个 `const StringName` 在加载期冻结，稳态禁止构造/拼接字符串或修改 InputMap。
- **Action cancellation**：只有InputSystem私有`release_movement_actions_and_clear(tick_revision)`可对四个专用movement action调用`Input.action_release`并在验证tick后clear carrier；Host lifecycle与其他项目代码均不得直接release。helper不写Input顶层state或三个enable字段；caller必须先发布与调用前state对应的合法tuple：ACTIVE先经`commit_consumer_closed()`成为LOCK_PENDING=`true/false/true`，既有locked state保持`true/false/true`，IDLE cleanup保持`true/false/false`。helper每次先读取四action的`is_action_pressed`与raw strength、carrier、gesture gate与pending release；action dirty定义为`pressed || raw_strength != 0.0`，对每个dirty action恰调一次`action_release`。无论release后action验证成功或失败，helper都必须在返回前通过trusted commit完整把carrier写为`{ZERO,false,-1,tick_revision}`并清除pending release，关闭gesture/consumer gate且保持调用前合法tuple；随后验证四action同时满足`pressed=false && raw_strength==0.0`。仍dirty时返回`ACTION_CLEAR_FAILED`，但PlayerController不再可能消费旧carrier，也不存在待处理旧release；ACTIVE来源保持LOCK_PENDING而不回滚，IDLE仍不得开启shield service。仅当四action已clean、carrier已为当前tick的clear值、gate已closed且无pending release时，同tick重复cancel才是不刷新`just_released`的无副作用OK；任一action在两次cancel间重新pressed或raw非ZERO，即使tick不变也必须再次release。较旧tick返回STALE_TICK。其他系统禁止消费四action的just-pressed/just-released状态。
- **异步错误闩锁与必达观察**：InputSystem私有维护`safe_close_tick_revision`。`initialize`必须在callback连接数=0时依次完成argument、非负权威tick、action、Host与geometry全部验证，成功后seed该tick，最后才连接Host/shield/VJ；seed/验证完成前不得连接或开放任何可触发callback的节点。之后只有在无pending latch、除`service_pending_input_fault`外的同步API通过argument/tick/state/phase验证后，才以该已接受的权威技术tick单调更新；无pending的service只验证参数/state并返回OK，绝不读取以外的mutable state、写`safe_close_tick_revision`或改变任何后续可观察结果。Host/shield signal callback只能写预分配gesture/shield-bank/choice state与first-error-wins`pending_input_status`并消费其GUI event；lifecycle/geometry callback另可执行Core Rule 2唯一允许的hit-route disable。它们不得执行safe close、直接迁移GameRoot/Input state、写movement carrier或写actions。除只读`is_choice_input_blocked`外，首个随后进入的同步Public API在验证本次caller tick前原子capture并ack该latch到只读`first_async_failure_status` telemetry，设置`async_fault_consumed=true`并把`pending_input_status`恢复OK，再执行唯一一次state-aware `ASYNC_SAFE_CLOSE`：忽略本次尚未验证的argument/tick；若调用前state=ACTIVE，先经`commit_consumer_closed()`原子变为LOCK_PENDING=`true/false/true`，再设shield STOP并使用内部`safe_close_tick_revision` release当前dirty actions及clear carrier/pending release；若调用前state∈`{LOCK_PENDING,FROZEN,RESUME_LOCKED}`则保持`true/false/true`后执行STOP/clear；若调用前state=IDLE则保持`true/false/false`与PREACTIVE_DISCARD、不得开启bank service，只执行适用的clear并等待直接teardown。返回captured root status且不再评估本次caller参数。GameRoot的`PROCESS_MODE_ALWAYS` paused control pump必须在每个BATTLE_PAUSED/RESUME_PREPARING main-loop iteration及每次choice/resume入口先调用`service_pending_input_fault(tick_revision)`；无latch时为上述真正no-op，有latch时在引擎恢复派发main-loop后的最迟下一iteration返回capture的精确status并进入fault。teardown不要求先调用service：若它是任意状态中的首观察者，同一调用必须capture+ack；ACTIVE先完成上述consumer-close，IDLE保持service=false，locked保持service=true；随后先以callback不可观察的terminal局部提交原子置`TERMINATED=false/false/false`并撤销bank/choice/pending latch写权，再完成filter、断连、移出与释放，最终返回capture的根status且不要求第二次teardown。该非OK返回表示本局根因而非teardown未执行；ASYNC_SAFE_CLOSE自身的action-clear后验失败只追加suppressed `ACTION_CLEAR_FAILED` diagnostic，captured root status不被覆盖且consumer保持closed。terminal commit后的迟到callback只能追加suppressed diagnostic，不得重填pending latch或bank。新battle的新实例才重置`async_fault_consumed/first_async_failure_status`。GameRoot保存首次返回的status为权威根因。
- **Carrier schema**：

```gdscript
class_name MovementIntentCarrier
extends RefCounted

var direction: Vector2 = Vector2.ZERO
var is_active: bool = false
var press_generation: int = -1
var written_tick: int = -1

func write(next_direction: Vector2, generation: int, tick_revision: int) -> void:
    direction = next_direction
    is_active = next_direction != Vector2.ZERO
    press_generation = generation
    written_tick = tick_revision

func clear(tick_revision: int) -> void:
    direction = Vector2.ZERO
    is_active = false
    press_generation = -1
    written_tick = tick_revision
```

`MovementIntentCarrier.write/clear`是InputSystem私有、trusted且无返回值的字段提交器，不承担校验或status归属。carrier字段精确保持`{direction,is_active,press_generation,written_tick}`，不新增battle/config/player identity；PlayerController从同次调用的matching `PlayerPhaseContextV1`验证这些identity。`press_generation`是Host已接受的新press generation，不冒充内置节点私有touch index。触点仍在唯一deadzone内时允许`direction=ZERO、is_active=false、press_generation>=1`；只有release、pause cancel、ending/fault的同步clear后generation才回到`-1`。InputSystem的`commit_movement(...) -> int`与`commit_clear(...) -> int`先在局部值上完整验证direction finite、单位幅值、generation与tick，再恰调用一次trusted write/clear；失败不调用carrier方法、不产生部分字段写，并由Public API返回精确status。

### Public API and Status

`InputStatus` 是 primitive int enum；只有 `OK` 属于 success class：`OK`、`INVALID_ARGUMENT`、`INVALID_CONFIG`、`INVALID_INPUT_MAP`、`NON_FINITE_INPUT`、`WRONG_STATE`、`WRONG_PHASE`、`STALE_TICK`、`GENERATION_EXHAUSTED`、`ACTION_CLEAR_FAILED`、`JOYSTICK_REBUILD_FAILED`。错误归属固定为：几何/候选配置/manifest前置失败=`INVALID_CONFIG`；四个专用action缺失、重复或存在非空event binding、或生产emulation未关闭=`INVALID_INPUT_MAP`；VJ实例候选替换、旧回调断开、新实例登记或树操作失败=`JOYSTICK_REBUILD_FAILED`，不得用后者掩盖更早的配置或InputMap错误。

| `run_phase(phase,context,lease_id)->int` | GameRoot / Input state ACTIVE或LOCK_PENDING，且GameRoot处于对应ACTIVE/PAUSE_PENDING合法phase | MOVEMENT_COMMIT完整写carrier，或barrier完整cancel | carrier保持调用前值；NON_FINITE_INPUT或异步错误闩锁按安全规则完整clear |
| `cancel_input(reason,tick_revision)->int` | GameRoot / 仅允许下方state×reason矩阵 | ACTIVE来源先由`commit_consumer_closed()`原子进入LOCK_PENDING=`true/false/true`，再设shield STOP、clear actions/carrier；既有locked state保持`true/false/true`后STOP/clear；IDLE ending/fault保持`true/false/false`、PREACTIVE_DISCARD并clear，随后直接teardown | 前置argument/tick/state/reason失败零修改；close commit后的`ACTION_CLEAR_FAILED`仍强制carrier当前tick精确clear、pending release空，ACTIVE来源保持LOCK_PENDING=`true/false/true`，locked保持原合法tuple，IDLE保持`true/false/false`，均不得回滚或部分开放 |
| `service_pending_input_fault(tick_revision)->int` | GameRoot paused control pump / IDLE、LOCK_PENDING、FROZEN或RESUME_LOCKED；每个Paused/Resume main-loop iteration及choice/resume入口先调用 | 无pending latch时只验证参数/state，且包括`safe_close_tick_revision`在内完全零修改后返回OK；有latch时先原子capture+ack、使用调用前内部`safe_close_tick_revision`执行一次state-aware `ASYNC_SAFE_CLOSE`并返回captured status：IDLE保持`true/false/false`，三种locked state保持`true/false/true` | 无latch时argument/stale/state失败零修改；有latch时不采用或继续验证本次caller tick，captured非OK是权威root failure，GameRoot同iteration进入fault cleanup；safe-close自身新失败只作suppressed diagnostic |
| `VirtualJoystickHost.ensure_rebuilt_after_invalidation(input_rebuild_revision,geometry_snapshot,tick_revision)->int` | GameRoot foreground/reconfigure preflight或RESUME_PREPARING / callbacks armed、shield enabled、ingress/gesture gate closed、carrier为当前tick精确clear值、pending release为空、四action均`pressed=false && raw=0` | 新revision时以initialize冻结的immutable candidate-config snapshot离树构建/validate，旧节点不可命中并用保存的同一Callable断signal、移出树并queue_free，VJ gesture epoch与shield epoch checked推进、旧shield bank清空，唯一新节点以`MOUSE_FILTER_IGNORE`入树并完成identity/signal登记；同revision仅在二元版本组、geometry与candidate-config的fingerprint及完整canonical fields均相等，且`registered_active_vj_count==1`、identity/signal/tree ownership均匹配时才可无副作用返回OK；失败后active VJ为0时不得以同revision幂等短路恢复 | 参数非法=`INVALID_ARGUMENT`；较旧revision或同revision任一identity字段不等=`STALE_TICK`；callbacks/gate/shield/state前置非法=`WRONG_STATE`；new revision geometry/config domain非法或instance-frozen config漂移=`INVALID_CONFIG`；registered active VJ数量不是1、identity/signal/tree ownership不匹配或candidate构造/属性/validate、old remove、new add、signal connect故障=`JOYSTICK_REBUILD_FAILED`；action/carrier/pending release不clean=`ACTION_CLEAR_FAILED`；epoch overflow=`GENERATION_EXHAUSTED`。所有failure保持consumer closed、carrier精确clear并按阶段矩阵清理 |
| `VirtualJoystickHost.is_choice_input_blocked()->bool` | BattleUI与GameRoot / 只读；任意pause UI press前、进入RESUME_PREPARING前及每个可重入resume stage boundary | 旧VJ claim或shield-held bank任一非空时true；两者为空且所需preflight完成时false | 无failure通道、无状态mutation；不消费pending async latch |
| `teardown(tick_revision)->int` | GameRoot / BATTLE_ENDING或fault cleanup | ACTIVE来源先完成合法consumer-close；IDLE保持service=false，locked保持service=true。随后在任何filter/tree/Callable操作前单一局部提交`state=TERMINATED、callbacks/runtime/service=false/false/false`并撤销bank/choice/pending latch写权、清空bank，再使节点不可命中、断signal、移出树并queue_free且carrier clear；若本调用首次观察async latch，同次capture/ack+state-aware safe-close+terminal cleanup并返回captured root status | 保持consumer closed并记录teardown自身首错；terminal commit已完成时后续cleanup failure不得回滚三字段，迟到callback只作suppressed diagnostic且不得重填latch/bank；返回captured root status不表示cleanup未执行 |

同步API的first-error precedence冻结为：尚未消费的`pending_input_status`（first-error-wins，命中则capture+ack并以内部`safe_close_tick_revision`执行一次`ASYNC_SAFE_CLOSE`，不读取或采用本次未验证参数；teardown继续完成同调用terminal cleanup）→ `INVALID_ARGUMENT` → initialize或rebuild domain的`INVALID_CONFIG`及initialize专属`INVALID_INPUT_MAP` → `STALE_TICK` → `WRONG_STATE` → `WRONG_PHASE` → 本次采样/派生错误（如`NON_FINITE_INPUT/ACTION_CLEAR_FAILED`）。initialize/`IDLE→ACTIVE`观察到preactive invalidation latch时使用现有`WRONG_STATE`，但GameRoot只在BATTLE_LOADING且该typed latch为true时把它分类为安全lifecycle abort；其他`WRONG_STATE`仍是普通failure。`ensure_rebuilt_after_invalidation`的精确specialization为pending-first后`INVALID_ARGUMENT → STALE_TICK → WRONG_STATE → INVALID_CONFIG → ACTION_CLEAR_FAILED → GENERATION_EXHAUSTED → JOYSTICK_REBUILD_FAILED`；后者只覆盖candidate/tree/signal/登记阶段，不能覆盖更早root status。无pending latch时，普通验证命中前项后不得继续执行后项或任何mutation；pending latch是唯一预先冻结的safe-close例外，teardown是唯一在返回captured status前继续terminal cleanup的API。`is_choice_input_blocked`是唯一不消费latch的Public read；`service_pending_input_fault`是Paused/Resume下的必达同步observer，不允许用bool read代替。InputSystem引用仅由GameRoot私有持有，mutation API的caller约束通过scene ownership与静态call-site审计实施，不设计可伪造的运行时caller token；验收矩阵须证明项目中不存在GameRoot以外caller。`cancel_input`不接收phase参数，因而其非法state/reason项返回`WRONG_STATE`；`WRONG_PHASE`只由`run_phase`的phase/lease校验返回。同tick重复cancel只要state/reason属于下表合法清理路径即为OK；是否重新`action_release`由Action cancellation的当前脏状态决定，不得因tick未变返回WRONG_STATE。

#### `cancel_input` state × reason 矩阵

| Input state | reason / GameRoot path | Result | State/postcondition |
|---|---|---|---|
| `ACTIVE` | `MANUAL/LEVEL_UP/TREASURE_CHOICE/RISK_CHOICE/APP_BACKGROUND/INPUT_GEOMETRY_CHANGED`，barrier或foreground preflight | `OK`或safe-clear类`ACTION_CLEAR_FAILED` | 前置验证全部通过后先以`commit_consumer_closed()`单一局部提交`ACTIVE→LOCK_PENDING + true/false/true`，再设STOP shield，最后clear；clear失败保持LOCK_PENDING tuple并进入fault，不回滚ACTIVE |
| `LOCK_PENDING` | 上述任一pause reason，direct/drain/preflight同tick或后续合法重调 | `OK`或`ACTION_CLEAR_FAILED` | 不迁移并保持`true/false/true`；按当前dirty predicate重做或clean no-op，clear failure不改变tuple |
| `FROZEN` | `APP_BACKGROUND/INPUT_GEOMETRY_CHANGED` reconfigure preflight | `OK`或`ACTION_CLEAR_FAILED` | 保持FROZEN=`true/false/true`；STOP/clear成功后才可rebuild，失败直接fault cleanup |
| `RESUME_LOCKED` | `RESUME_PREPARING` | `OK`或`ACTION_CLEAR_FAILED` | 保持RESUME_LOCKED=`true/false/true`；STOP/clear成功后才可开Grid/Pool lease，失败直接fault cleanup |
| `RESUME_LOCKED` | `APP_BACKGROUND/INPUT_GEOMETRY_CHANGED`，且尚未调用首次Grid/Pool matching publish | `OK`或`ACTION_CLEAR_FAILED` | 保持RESUME_LOCKED=`true/false/true`；按当前dirty predicate release并验证actions/carrier/pending release clean；成功后才可abort/close与rollback FROZEN，失败走emergency cleanup |
| `IDLE` | `BATTLE_ENDING/CONTROLLED_FAULT` loading/preactive cleanup | `OK` | 保持IDLE=`true/false/false`与PREACTIVE_DISCARD；shield bank service写次数0，clear后直接teardown |
| `ACTIVE` | `BATTLE_ENDING/CONTROLLED_FAULT` cleanup | `OK`或safe-clear类`ACTION_CLEAR_FAILED` | 先原子`ACTIVE→LOCK_PENDING + true/false/true`，再STOP/clear；无论clear后验均保持locked tuple并直接teardown |
| `LOCK_PENDING/FROZEN/RESUME_LOCKED` | `BATTLE_ENDING/CONTROLLED_FAULT` cleanup | `OK`或safe-clear类`ACTION_CLEAR_FAILED` | state不迁移且保持`true/false/true`，STOP/clear后直接teardown；clear failure只追加root/suppressed分类，不改变tuple |
| `TERMINATED` | 任意reason | `WRONG_STATE` | 零修改，保持TERMINATED |
| 其他state×reason组合 | 任意直接调用 | `WRONG_STATE` | 零修改；不得由InputSystem推断或补写GameRoot phase |

## Formulas

### F1 — Action Vector 到 Movement Intent

```text
# F1 is a total function over a verified sample and the current Input FSM.
# Only GameRoot's MOVEMENT_COMMIT path may request this sample.
sample = verified_action_sample(
    touch_move_left,
    touch_move_right,
    touch_move_up,
    touch_move_down,
    0.0,
    input_map_revision,
    action_binding_manifest_hash
)

if not sample.ok:
    return sample.status  # INVALID_INPUT_MAP / INVALID_CONFIG; no carrier write
action_vector = sample.action_vector
if not is_finite(action_vector.x) or not is_finite(action_vector.y):
    return NON_FINITE_INPUT  # InputSystem同步safe-clear，GameRoot fault
elif state != ACTIVE or not callbacks_armed or not runtime_ingress_armed \
        or not fresh_press_gate_open or claim_state != CLAIM_ACTIVE \
        or claim_epoch < 1 or claim_generation < 1 \
        or pending_release_present or terminal_or_lock_pending:
    out = Vector2.ZERO
elif action_vector == Vector2.ZERO:
    out = Vector2.ZERO
else:
    scale = max(abs(action_vector.x), abs(action_vector.y))  # finite且>0
    scaled = action_vector / scale
    scaled_length = sqrt(scaled.x * scaled.x + scaled.y * scaled.y)
    out = scaled / scaled_length
    if not is_finite(out.x) or not is_finite(out.y) or abs(out.length() - 1.0) > 1e-6:
        return NON_FINITE_INPUT
```

F1的错误优先级固定为：`verified_action_sample`配置/manifest状态 → action vector finite → Input FSM admission gate → ZERO判定 → scale-first归一化。任何gate失败只能输出ZERO，不能遮蔽已验证sample的`NON_FINITE_INPUT`；`NON_FINITE_INPUT`与`INVALID_*`均先执行同步safe-clear，再由GameRoot观察并fault。

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `action_vector` | Vector2 | 每轴finite且`[-1,1]`，幅值`[0,√2]`；生产引擎通常≤1 | 四个专用 InputMap action | VirtualJoystick 已施加唯一 deadzone 后的方向/强度；仍须先做finite守卫 |
| `sample` | typed `VerifiedActionSampleV1` | `ok/status/action_vector/revision/hash` | InputMap + four actions | 只允许当前MOVEMENT_COMMIT读取；revision/hash必须匹配已验证配置 |
| `fresh_press_gate_open` | bool | true/false | press/release adapter | pause/恢复后阻止旧触点重放 |
| `claim_state` | enum | `NO_CLAIM/CLAIM_ACTIVE` | VJ identity FSM | 仅当前epoch/generation的active claim可产生movement |
| `claim_epoch/generation` | i64 | `>=1` when active | VJ/Host transaction | 旧节点、pending release或terminal边界不可借用旧claim |
| `scale/scaled_length` | float | finite且`>0`（仅非ZERO分支） | derived | scale-first安全归一化，避免有限极小向量平方下溢；不是第二deadzone |
| `out` | Vector2 | finite，幅值 `{0,1}` | derived | 写入 carrier 的二元移动方向 |
| `deadzone_ratio` | float | `[0.05,0.30]` | VirtualJoystick | 唯一 deadzone owner；MVP 默认 `0.15` |

**边界**：finite检查严格早于ZERO/gate/归一化分支。内置 VirtualJoystick 只有在触点距离严格大于 `deadzone_ratio × clampzone_radius` 时才产生非零 action strength；因此 `0.99×` 与 `1.00×` 阈值输出 ZERO，`1.01×` 输出非零 action，F1再以scale-first算法归一化为单位向量。该算法对任意finite非ZERO Vector2均不靠任意epsilon判零，不引入第二deadzone；若任一步产生非finite或不能满足单位后置条件则返回`NON_FINITE_INPUT`。InputMap event list为空、action deadzone与`Input.get_vector` deadzone均为`0.0`。

**总函数边界**：状态、callbacks、runtime ingress、fresh gate、claim identity、pending release、terminal/LOCK_PENDING与sample revision/hash均在采样前按固定顺序验证；任一不满足只返回ZERO且不写carrier。只有`ACTIVE + callbacks_armed + runtime_ingress_armed + fresh_press_gate_open + CLAIM_ACTIVE + 无pending release + 无terminal/lock`的当前claim，且verified sample为finite时，才进入归一化；配置/InputMap错误仍返回精确status并按safe-clear规则处理。`F1`不负责推进FSM、不消费pending release、不把ZERO解释为release。

**示例**：`action_vector=(0.25,-0.25)` 且所有FSM前置满足 → `out≈(0.707,-0.707)`；`action_vector=ZERO` 或任一claim/lifecycle gate closed → `out=ZERO`。

PlayerController下游公式不是F1的一部分：`velocity=out×4.5 units/s`，`displacement=velocity×gameplay_dt`，`candidate=readback_real_t32(position+displacement)`；Player只做`full_footprint_domain_guard`并原样提交合法candidate，不做Stage边界clamp。

### F2 — Safe Viewport 比例几何

```text
# Checked preconditions run before any inverse or inset transform.
require finite_rects_and_transform_inputs()
require safe_rect_display.is_non_empty() and window_client_rect_display.is_non_empty()
require safe_rect_clipped_display.is_non_empty()
require viewport_to_window_physical.is_finite()
require viewport_to_window_physical.determinant != 0.0
require residual_navigation_gesture_insets_physical are integer >= 0
require transform domain supports axis-aligned inset or return INVALID_CONFIG

safe_rect_display = DisplayServer.get_display_safe_area()
window_client_rect_display = SafeViewportGeometryProvider.get_window_client_rect_in_display(
    current_screen, window_id
)
safe_rect_clipped_display = intersection(safe_rect_display, window_client_rect_display)
safe_corners_window_physical = map_each(
    point -> point - window_client_rect_display.position,
    safe_rect_clipped_display.corners
)
viewport_to_window_physical = host.get_viewport().get_screen_transform()
window_physical_to_viewport = checked_affine_inverse(viewport_to_window_physical)
safe_corners_viewport = map_each(window_physical_to_viewport, safe_corners_window_physical)
safe_corners_local = map_each(host.make_canvas_position_local, safe_corners_viewport)
safe_viewport = axis_aligned_rect(safe_corners_local)  # 旋转/剪切或退化则 INVALID_CONFIG
residual_navigation_gesture_insets_physical = geometry_manifest.residual_navigation_gesture_insets
residual_navigation_gesture_insets_local = transform_axis_aligned_insets(
    residual_navigation_gesture_insets_physical,
    window_physical_to_viewport,
    host.viewport_to_local
)
interactive_safe_viewport = inset_rect(safe_viewport, residual_navigation_gesture_insets_local)
max_abs_window_coordinate = max_abs_component(safe_corners_window_physical)
roundtrip_tolerance_physical = max(
    1e-4,
    4.0 * ulp_real_t(max(1.0, max_abs_window_coordinate))
)

safe_short_side = min(interactive_safe_viewport.size.x, interactive_safe_viewport.size.y)
input_region_height = interactive_safe_viewport.size.y × input_region_height_fraction
movement_rect = Rect2(
    interactive_safe_viewport.position.x,
    interactive_safe_viewport.end.y - input_region_height,
    interactive_safe_viewport.size.x,
    input_region_height
)
joystick_size = safe_short_side × joystick_size_fraction
tip_size = joystick_size × tip_size_ratio
clampzone_radius = joystick_size × 0.5 × clampzone_ratio
deadzone_radius = clampzone_radius × deadzone_ratio
```

| Variable | Type | Range | Default | Description |
|---|---|---|---|---|
| `safe_rect_display` | Rect2i | non-empty | OS-derived | display physical坐标安全区；不得直接当Canvas logical rect |
| `window_client_rect_display` | Rect2i | non-empty | native root window | 当前window client rect在同一display physical坐标系的位置/大小；不含title bar/border |
| `safe_rect_clipped_display` | Rect2i | non-empty | intersection | display safe rect与window client rect交集；交集为空则`INVALID_CONFIG` |
| `window_physical_to_viewport` | Transform2D | finite、invertible | inverse of current Viewport screen/final stretch transform | window client physical到logical viewport的权威逆变换；禁止用`window_size/screen_size`猜测缩放 |
| `roundtrip_tolerance_physical` | float | finite、`>=1e-4`且通常`<0.01 px` | target `real_t` + coordinate magnitude | window→viewport→window四角往返容差；按目标export精度的4 ULP放宽，不以固定阈值误拒合法float32变换 |
| `safe_viewport` | Rect2 | finite、axis-aligned、宽高`>0` | transform-derived | 依次经display→window→viewport/canvas→Host local转换后的权威安全区 |
| `residual_navigation_gesture_insets_physical` | Vector4i `{left,top,right,bottom}` | 四边integer且`>=0` | frozen per-artifact geometry manifest | display safe area尚未覆盖的系统返回/Home手势保留区；manifest证明已覆盖时四边均为0 |
| `interactive_safe_viewport` | Rect2 | finite、axis-aligned、宽高`>0`且包含于safe_viewport | transformed safe rect minus residual insets | movement与交互UI可起按的权威区域；不得与系统手势保留区重叠 |
| `safe_short_side` | float | finite, `>0` | device-derived | Godot stretch之后、同一Canvas坐标系中的safe viewport短边 |
| `input_region_height_fraction` | float | `[0.35,0.55]` | `0.45` | movement rect占safe viewport高度比例 |
| `input_region_height` | float | finite, `>0`且`≤safe_viewport.size.y` | derived | Dynamic起按区高度 |
| `movement_rect` | Rect2 | finite且包含于interactive_safe_viewport | derived | VirtualJoystick与shield基础可命中区域；UI exclusion由上层Control截获 |
| `joystick_size_fraction` | float | `[0.18,0.28]` | `0.22` | 摇杆直径占safe短边比例 |
| `tip_size_ratio` | float | `[0.35,0.60]` | `0.45` | thumb直径占摇杆直径比例 |
| `clampzone_ratio` | float | `[0.75,1.25]` | `1.0` | 最大拖动半径倍率 |
| `deadzone_ratio` | float | `[0.05,0.30]` | `0.15` | 唯一deadzone倍率 |
| `initial_offset_ratio` | Vector2 | 每轴finite且`[0,1]` | `(0.5,0.5)` | Control内部初始中心比例；Dynamic press后由引擎移动origin |

所有量最终都在同一Godot logical viewport/Host local transform下计算，不读取设备DPI，也不假定display physical px与window client px为1:1。Provider只支持当前native root window；它必须使用Godot当前Viewport的screen/final stretch transform构造`window_physical_to_viewport`，并对每个四角验证`window → viewport → window`往返误差`<=roundtrip_tolerance_physical`。`ulp_real_t(x)`定义为目标export中`x`到同方向相邻可表示finite值的距离，由Provider中固定的目标`real_t`相邻bit-pattern helper计算并以float32/float64边界fixture校验，不依赖不存在的引擎便利API；identity/1.1 scale、1080p/4K、非零display origin均须有positive fixture，超过容差的perturbed inverse须有negative fixture。`host.make_canvas_position_local()`只能接收上一步得到的viewport coordinate，不得接收window physical coordinate。每个artifact的geometry manifest必须同时记录OS navigation mode、四边residual inset及“已由display safe area覆盖/另行扣除”的来源；字段缺失或扣除后interactive safe rect退化均为`INVALID_CONFIG`。移动端 future-port asset冻结为portrait base logical canvas`720×1280`；当前Steam asset使用landscape base logical canvas`1280×720`，两者均使用`canvas_items`/`expand`，不得跨profile混用。Host与BattleUI CanvasLayer编号/scene-tree顺序由BattleUI scene冻结但必须满足本GDD先交互UI、再shield、最后VJ的输入路由。未建立对应profile的`project.godot`前IG-IS4保持BLOCKED，不得以引擎默认值替代。BATTLE_LOADING必须验证display safe/window client交集非空、window→viewport变换finite/invertible且往返误差合格、四角转换为有限/axis-aligned/非退化矩形，residual inset合法、`input_region_height_fraction`及全部比例在范围内，派生`movement_rect`包含于interactive safe viewport，且`joystick_size`、`tip_size`、`clampzone_radius`、`deadzone_radius` finite并满足`joystick_size>tip_size>0`、`clampzone_radius>0`。例：移动端转换后的interactive safe viewport为`720×1280` logical px时，默认`input_region_height=576`、`joystick_size=158.4`、`tip_size=71.28`、`clampzone_radius=79.2`、`deadzone_radius=11.88` logical px。

`SafeViewportGeometrySnapshot`是构建后不可变的typed value，字段至少为`{input_rebuild_revision,geometry_revision,window_id,current_screen,safe_rect_display,window_client_rect_display,window_physical_to_viewport,viewport_to_host_local,safe_viewport,residual_navigation_gesture_insets_physical,residual_navigation_gesture_insets_local,interactive_safe_viewport,movement_rect,joystick_size,tip_size,clampzone_radius,deadzone_radius,real_t_precision,roundtrip_tolerance_physical,geometry_fingerprint}`。`geometry_revision`是`BattleInputGeometryRelay`唯一递增的源几何版本，`input_rebuild_revision`是GameRoot为一次coalesced rebuild提交分配的版本；两者不是别名。每个`INPUT_GEOMETRY_CHANGED`必须携带二元版本组及同一份完整snapshot；同一process frame只保留最新几何版本并最多提交一次rebuild，任何checkpoint都同时比较二元版本组与invalidation latch。Host在initialize同时冻结不可变typed `VirtualJoystickCandidateConfigSnapshot={candidate_config_id,joystick_mode,visibility_mode,action_left,action_right,action_up,action_down,deadzone_ratio,clampzone_ratio,joystick_size_fraction,tip_size_ratio,initial_offset_ratio,theme_resource_uid,theme_content_hash,candidate_config_fingerprint}`；所有candidate setter只能读取该snapshot，实例存活期不接受配置替换，变更必须teardown并创建新InputSystem/Host实例。所有float在finite验证后将`-0.0`规范为`+0.0`；除revision/ID与fingerprint自身外，几何字段和candidate-config字段分别按上述固定顺序形成canonical sequence。两个fingerprint都只允许作为快速不等预筛或diagnostic：同revision幂等必须先要求两个fingerprint exact equality，再逐字段比较完整geometry与candidate-config canonical sequence exact equality；任一字段不同即返回`STALE_TICK`且不得跳过rebuild，禁止仅凭hash相等、epsilon、resource/object identity或可变对象指针判相等。若fingerprint需要跨进程/跨artifact持久化，届时必须由manifest另行冻结schema version、算法、位宽、字节序；未冻结时不把fingerprint值本身作为跨进程契约。

**F2 checked precondition / oracle**：先验证所有Rect/Transform输入finite、`Rect2i`采用半开区间`[position,end)`且display/window交集非空，再验证变换行列式非零并调用`checked_affine_inverse`；任何非finite、不可逆或超出支持域的旋转/剪切均在读取四角前返回`INVALID_CONFIG`。`transform_axis_aligned_insets`不得把旋转/剪切后的Vector4i边界伪装成local轴向量；无法证明等价时同样返回`INVALID_CONFIG`。四角只在这些前置通过后转换，最终还必须满足finite、axis-aligned、非退化、roundtrip tolerance与inset后包含关系。

## Edge Cases

### A. 输入值与配置

- `action_vector` 含 NaN/inf：InputSystem 返回 `NON_FINITE_INPUT`，原子 clear carrier；GameRoot 集成层据 status 进入 CONTROLLED_FAULT。
- F2任一display safe/window client交集为空、window/viewport/Canvas转换失败或往返误差超过精度感知容差、四角非axis-aligned/退化、`input_region_height_fraction`或其他比例非finite/越界、movement rect越出safe viewport，或派生结果不满足`joystick_size>tip_size>0`、`clampzone_radius>0`：BATTLE_LOADING返回`INVALID_CONFIG`，不开放battle input。
- 四个 action 缺失、重复、event list非空，或生产 mouse-to-touch emulation未关闭：返回`INVALID_INPUT_MAP`，不开放battle input。
- geometry/candidate config、manifest字段/容量、变换逆或registered active VirtualJoystick数量/identity不等于1：返回`INVALID_CONFIG`；候选节点构造/替换、旧回调断开、新节点登记或树操作失败才返回`JOYSTICK_REBUILD_FAILED`。
- action vector 为 ZERO：carrier 写 ZERO；不除零。

### B. 触摸路由与多点

- 无 active movement touch 时按暂停按钮：UI 消费事件，carrier 保持 ZERO。
- 已有 movement touch，第二触点按暂停按钮：pause intent 接受前 carrier 保持第一触点方向；barrier 接受后统一 cancel 并 clear。
- 已有 movement touch，第二触点进入移动区：忽略；第一触点 release 后第二触点仍 held 也不得自动晋升，须 release 后新 press。
- touch press 落在移动区外或排除 rect 内：不得驱动四个 movement action。
- UI routing不以`z_index`作为输入顺序证明。固定scene-tree/CanvasLayer顺序为交互pause/choice UI→Host唯一持有的typed consumer-closed movement shield→VirtualJoystick；交互Control与shield使用effective `MOUSE_FILTER_STOP`并在命中时`accept_event()`。VirtualJoystick基础Control固定覆盖F2 movement rect；活动UI截获自身exclusion rect，shield在consumer closed时截获其余完整movement rect，不调用摇杆geometry setter。单个press不得同时改变UI与movement action；已有VJ touch-focus release/cancel仍交给原VJ，shield命中的press/motion/release/cancel只更新其预分配held-touch bank。ACTIVE时shield保持在树且`PROCESS_MODE_ALWAYS`，但effective filter固定为IGNORE；consumer closed或held-drain时effective filter固定为STOP，ancestor递归mouse/process不得禁用。

### C. 暂停、后台与恢复

- pause intent latched：barrier内完成前置验证后，先由`commit_consumer_closed()`原子发布完整`LOCK_PENDING + callbacks/runtime/service=true/false/true`，再把完整movement-rect shield设为effective STOP，最后调用`release_movement_actions_and_clear(tick_revision)`释放四action、清零carrier/pending release并关闭gesture/consumer gate；仅当当前内置节点仍有claim时进入ignored-until-release，否则进入`WAIT_FRESH_PRESS`。普通pause不得把claimed VJ设为IGNORE；shield只阻止new press，不夺取旧touch-focus release。
- PAUSE_PENDING drain：InputSystem 已锁定；不得采样或产生新 intent。
- BATTLE_PAUSED/RESUME_PREPARING：任何旧drag/release/cancel不得触发choice或movement；paused control pump先调用`service_pending_input_fault`，BattleUI每次choice press前再读取`is_choice_input_blocked()`，只接受返回false后的新press。
- APP_BACKGROUND：不假定系统一定派发release；lifecycle callback同步把active node设为不可命中新press并设置`foreground_input_blocked=true`，但不在callback写action/carrier/state或重建。background barrier/foreground preflight先由InputSystem cancel，随后Host按`input_rebuild_revision`与instance-frozen candidate config离树配置candidate、精确disconnect并移出/queue_free旧节点、推进epoch、重建并验证唯一registered新节点；在PAUSE_PENDING/BATTLE_PAUSED/RESUME_PREPARING它仍不可命中。preflight/FROZEN/choice完成后仍保持Paused，必须由玩家明确readiness/Continue才允许ACTIVE；该press不得兼作movement press。旧epoch迟到signal无效，不等待永远不会到达的release。
- safe geometry invalidation：InputSystem-owned `BattleInputGeometryRelay` 挂在 battle `Window`/目标Viewport边界，接收窗口尺寸、safe-area、orientation与stretch相关 signal/notification，读取并 canonicalize 完整geometry snapshot，checked推进唯一的`geometry_revision`，再由GameRoot为coalesced rebuild分配`input_rebuild_revision`并向Host转发携带二元版本组的typed `INPUT_GEOMETRY_CHANGED`。不得假定Control Host会收到Window-only通知（包括`NOTIFICATION_WM_SIZE_CHANGED`）。Host收到relay后同步关闭new-press ingress并latch invalidation；即使内置节点已静默reset，也只能使action归零，不能直接改carrier。GameRoot在下一安全barrier按同型安全协议cancel并以二元版本组对应的新geometry snapshot重建；若应用始终foreground且无MANUAL/APP_BACKGROUND/choice残留，FROZEN成功后可自动resume。active节点生命周期内禁止setter补丁式改尺寸。
- normal resume：恢复首tick仍为ZERO；旧VJ claim与shield-held bank任一非空都不得开放ACTIVE。resume开始前存在held时保持Paused；resume开始后新shield press按Core Rule 10在不可逆点前回Paused、点后无lease drain，matching release/cancel后的下一次新press才可建立generation。两类held从始至终都为空时，ACTIVE后的下一次新press即可建立generation。
- background resume：rebuild成功后保持Paused且gameplay phase、damage、timer均为0；合法readiness/Continue之后才发布ACTIVE，首tick仍为ZERO。readiness press不得成为movement；其后第一次新的OS movement press属于新epoch，可作为fresh press，旧节点及旧epoch不得重放movement。
- BATTLE_ENDING/CONTROLLED_FAULT：cancel 后进入 TERMINATED，本局不可恢复。

### D. APP_BACKGROUND / Geometry Invalidation 状态矩阵

| GameRoot state | 同步ingress动作 | 后续动作 |
|---|---|---|
| `BOOT/HOME/PREP` | 无battle Host；保持关闭 | 普通页面lifecycle恢复，不创建VJ |
| `BATTLE_LOADING` | runtime ingress始终未arm；touch走PREACTIVE_DISCARD；background/geometry只写preactive invalidation latch | initialize或IDLE→ACTIVE publish观察latch后返回`WRONG_STATE`并中止本次load、逆序cleanup回PREP；ACTIVE publish调用成功数=0，不得带partial Host恢复load或把该事件归technical fault |
| `BATTLE_ACTIVE` | invalidation callback将active node设IGNORE并立即阻断new press，latch pause reason/revision | 当前tick可完成则barrier cancel；否则foreground preflight cancel+rebuild后只准按GameRoot F2运行零gameplay-dt pause technical tick，不得运行普通Active tick |
| `PAUSE_PENDING` | 保持consumer/ingress closed，合并reason | foreground/reconfigure preflight完成前不得继续drain或开放UI输入 |
| `BATTLE_PAUSED` | movement ingress保持closed；choice gate同步blocked | preflight cancel+rebuild后仍保持Paused；旧claim被epoch淘汰后choice gate才可开放。纯geometry在其余gate完成后可自动resume；reason含APP_BACKGROUND时必须等待一个真实readiness/Continue |
| `RESUME_PREPARING` | 关闭ingress、启shield并latch新revision | 首次Grid/Pool matching publish前：先以invalidation reason执行dirty-aware cancel并验证actions/carrier/pending release clean，再恢复旧owner引用、abort每个candidate并matching close lease；Input仍FROZEN时不publish，已RESUME_LOCKED时走专用rollback边，再回Paused重做preflight。cancel/clean failure不发布FROZEN，但必须fault-abort/close至candidate/lease=0再teardown。不可逆点后：完成matching publish/lease/quarantine cleanup、保持consumer closed并fault teardown，禁止rollback/重试 |
| `BATTLE_ENDING/CONTROLLED_FAULT` | 永久关闭 | 不重建；走teardown，迟到signal只计诊断 |
| `SETTLEMENT` | battle Host已teardown；保持关闭 | 不创建/重建VJ，由页面lifecycle自行恢复 |

`ensure_rebuilt_after_invalidation`在构建任何candidate前按Public API的精确precedence验证revision/identity、callbacks/gate/shield/state、new-revision geometry与instance-frozen config、carrier/pending release及四action；任一前置failure均candidate build count=0。通过前置后，rebuild failure阶段后置条件冻结为：（1）epoch checked increment预检耗尽返回`GENERATION_EXHAUSTED`，不构建candidate；（2）candidate构建、属性设置或validate失败返回`JOYSTICK_REBUILD_FAILED`，旧节点已不可命中但仍在树、旧identity/epoch不变，candidate离树释放；（3）以保存Callable精确断signal或旧节点移出后、新节点登记前失败返回`JOYSTICK_REBUILD_FAILED`，旧节点queue_free、candidate释放，active identity为null且epoch/revision不推进；（4）新节点入树、direct signal连接或identity登记失败返回`JOYSTICK_REBUILD_FAILED`，新节点立即`MOUSE_FILTER_IGNORE`、精确断开已连Callable、移出并queue_free，active identity为null，epoch/revision不推进；（5）仅当new identity/Callable/tree ownership全部登记成功后才原子推进epoch/revision。所有failure均保持consumer closed、carrier/actions ZERO，不回滚为可命中旧节点；GameRoot保留精确root status进入fault cleanup，cleanup failure只作suppressed diagnostic。

### E. Tick hitch 与事件洪峰

- 不存在 selective participant skip；整 physics tick hitch 后，首个恢复 MOVEMENT_COMMIT 读取当前最新 action 状态。
- 一个 physics tick 前出现 120/240Hz drag burst 时，不排队保存历史坐标；InputMap 当前 action state为 last-write-wins，InputSystem下一 tick只读最新值。
- **支持平台触点有序性与终止边界**：当前内置VirtualJoystick路径只支持满足下列不变量的Android/iOS artifact：同一touch index在matching release/cancel完成分发前不得被新press复用；APP_BACKGROUND/geometry invalidation作为终止旧epoch的lifecycle边界后，不得在同index的新epoch press之后再投递旧epoch terminal；系统返回/Home或OS取消必须派发可观察`InputEventScreenTouch.is_canceled()`（shield据此删bank entry，Godot 4.7.1 VJ据非pressed分支发`released`并reset）或同步产生可执行rebuild的lifecycle边界。该边界必须由冻结的`SupportedTouchEventOrderingManifest`与真机原始event trace证明，字段至少含artifact/engine/export版本、OS、device model、navigation mode、display safe area、residual gesture insets、max concurrent touch count、lifecycle/edge-gesture场景、event sequence/index/pressed/canceled/timestamp与结论hash。违反该不变量的synthetic事件只用于fault injection并标记UNSUPPORTED，不要求现架构把无法辨识的旧terminal判为PASS；任一支持设备实测反序，或cancel既无事件也无lifecycle边界时，InputSystem不得进入implementation-ready，必须重开raw-touch identity/retired-index ingress、平台input bridge或自定义摇杆架构。

## Remediation boundary (2026-09-10)

`production/input-vertical-slice/` is a harness only; it does not satisfy the production implementation or integration gates. The 2026-09-10 review authorized static contract remediation, but `implementation-ready`, `integration-ready`, runtime/device evidence and `battle_ready` remain false until the manifest platform values, production InputMap/Settings assets, real GameRoot/PlayerController/BattleUI path and target traces exist.

本次整改后的跨系统最小合同如下：

- GameRoot是唯一phase scheduler、唯一`SceneTree.set_pause`/`Window.gui_disable_input` writer，也是唯一调用`run_phase(MOVEMENT_COMMIT)`的生产owner；PlayerController只读同tick matching carrier与`PlayerPhaseContextV1`，不得直接采样Input。`BATTLE_ACTIVE`消费`1/60` gameplay dt；`PAUSE_PENDING`只允许一次0-dt technical drain；`BATTLE_PAUSED`/`FROZEN`/`RESUME_LOCKED`不运行gameplay movement。
- `FROZEN`、pending release、shield bank、`service_pending_input_fault`与terminal close是生产生命周期合同，不得以`teardown=OK`的harness结果代替。`cancel_input`必须先提交consumer-closed tuple，再停止new press、清action/carrier并保留必要terminal drain；`teardown`首观察者必须在同一调用完成`TERMINATED={callbacks,runtime,service=false}`，迟到callback只作suppressed diagnostic。
- VJ rebuild是一次identity transaction：consumer closed、carrier/actions/pending-release clean后，构造并验证离树candidate，断开旧bound Callable并使旧epoch不可命中，checked推进epoch/revision，登记唯一新节点与signals，只有全部后置条件通过才允许同revision幂等OK；任一中间失败不得以counter/epoch递增冒充replacement成功。
- 状态与错误oracle统一：F1先判FSM/claim gate，F2先判finite/非空Rect/可逆变换/axis-aligned inset；`INVALID_CONFIG`、`INVALID_INPUT_MAP`与`JOYSTICK_REBUILD_FAILED`按上文固定边界，所有API仍保持first-error precedence与fail-closed。

## Tuning Knobs

### 系统拥有

- `deadzone_ratio`：默认 `0.15`，安全范围 `[0.05,0.30]`；影响抖动抑制与起步距离。唯一 deadzone owner。
- `input_region_height_fraction`：默认 `0.45`，安全范围 `[0.35,0.55]`；表示 safe viewport 自底向上的 Dynamic 起按区高度。
- `clampzone_ratio`：默认 `1.0`，安全范围 `[0.75,1.25]`；影响满量程所需拖动距离。
- `joystick_size_fraction`：默认 `0.22`，安全范围 `[0.18,0.28]`；决定摇杆直径相对safe viewport短边的比例。
- `tip_size_ratio`：默认 `0.45`，安全范围 `[0.35,0.60]`；决定thumb相对摇杆直径的比例。
- `initial_offset_ratio`：默认 `(0.5,0.5)`，每轴安全范围 `[0,1]`；Dynamic mode仅使用其作为未按下时的视觉初始位置。

### BattleUI / engine 拥有

- `joystick_mode=JOYSTICK_DYNAMIC`、`visibility_mode=VISIBILITY_WHEN_TOUCHED`：MVP 已冻结，不作为实现期 ADR。
- movement input region 的HUD/bottom-sheet exclusion和事件路由：BattleUI提供更高CanvasLayer且scene-tree顺序冻结的顶层Control，以overlay拦截exclusion rect；Host不因活动布局修改已入树VirtualJoystick geometry。禁止仅用`z_index`或任意shape mask的未声明实现。
- 四个 action 的 InputMap deadzone固定为 `0.0`，不是调优旋钮。

### 非旋钮

- `out`、`action_vector`、carrier字段和 `p95≤50ms` 下游停步目标均为契约或派生值，不得通过运营配置热改。

## Visual/Audio Requirements

InputSystem 不直接产生 VFX/SFX。Dynamic 摇杆只在触摸时显示：base ring alpha `0.25–0.35`，thumb alpha `0.5–0.7`，透明 hit region 不渲染；直径按F2计算。移动VFX归PlayerController/VFX；按钮与选择音归BattleUI/Audio。

最高密度怪潮、毒区和 Boss 预警截图中，即使摇杆可见也必须能辨识危险形状与方向；不能仅凭 alpha 数值宣称无遮挡。

## UI Requirements

- **移动区**：interactive safe viewport下方45%，排除顶部HUD、暂停按钮、display safe-area与residual navigation gesture inset以及任何活动bottom sheet；左右手均可在同一区域起按。Display safe rect先与window client rect求交，四角与residual inset再依次转为window client physical、viewport logical与Host local Canvas；所有区域与触点只在最后的Host local坐标系比较。
- **Dynamic 摇杆**：press 时在合法起按点建立 origin，release 后消失；不使用 Fixed/Following，不要求 handedness 设置或镜像配置。
- **暂停/选择交接**：普通pause若存在旧movement claim或shield-held touch，`is_choice_input_blocked()`保持true直到观察各自matching release/cancel；旧drag/motion/terminal不得被bottom sheet当作选择，也不得自动晋升为movement。consumer closed shield覆盖完整movement rect并阻止new VJ press，但位于可交互pause/choice UI下方，不阻挡合法UI press；两类held touch都为空时，pause UI下一次new press可立即选择且GameRoot才可开始resume。resume开始后的shield press按Core Rule 10等待/回Paused而非fault。APP_BACKGROUND/geometry rebuild按支持平台事件边界checked推进VJ与shield epoch并清空旧epoch bank，不等待缺失terminal；preflight完成后choice block才可解除，任何旧epoch迟到事件不得影响新claim。
- **选择 bottom sheet**：三选一为三条纵向choice row，整行可点击；每行热区高度为 `max(56 logical px, safe_height×0.044)`，相邻净间距为 `max(8 logical px, safe_height×0.00625)`，面板高度不超过safe viewport 50%，底部保留safe-area inset。内容超高时行内文字最多三行后省略，详情由同一行展开层承接；不得缩小热区。二选一沿用两条同型row。
- **单手任务**：左手与右手各自单持设备时，移动、暂停、选择、恢复移动均不得换握或借助另一只手。

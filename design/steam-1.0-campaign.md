# Steam 1.0 八章主流程与任务图 v0.1

日期：2026-09-11。状态：Working Baseline / Design Review Pending。关联[商业范围](steam-1.0-product-scope.md)、[内容矩阵](../production/steam-1.0-content-matrix.csv)、[系统迁移](../production/steam-1.0-system-migration.md)。本文件是产品内容设计，不是已冻结系统GDD或实现证据。

## 主流程结构

`新档 → 第1章M01…M08 → 第2章M01…M08 → … → 第8章M01…M07 → M08终局 → 结局/可选重玩`。

64个主线任务均顺序解锁；章节内部的机缘选择不另生成必走分支。每任务有固定主目标、场景、敌群与变体，不是64次同一生存计时。首次完成任务获得固定进度，失败只重试当前任务。每章前四任务使用场景1，后四任务使用场景2。

每章开始开放该章角色、3主动和3辅助，第一章除外：首名角色及其3+3从新档可用；风险与丹药教学在M01-03完成后开放。其他角色均可选，主线不要求换角色。进化需满足对应5级主动与辅助条件，配方随两者可用而公开。解锁不是立刻入选，SkillDraft仍需履行已冻结的合法候选/保底规则，扩池由owner设计。

所有任务须能保存退出/继续；只保存安全检查点还是完整局内快照由Save ADR裁定，在裁定和实现前该功能为BLOCKED。任务开始前显示目标、危险、预计时段、失败/退出后果与首次奖励。暂定不设置失败次数限制、真实时间等待或刷货币解锁主线。

## 六类目标的设计输入

| ID | 目标 | 核心交互 | 必须新增的合同 |
|---|---|---|---|
| S1-O-SURVIVE | 守候突破 | 在明示存活时段内保持生存；到达撤离窗口后完成任务，不要求每局必有Boss | 撤离窗口/存活时段及无Boss终态 |
| S1-O-BREAK | 破阵 | 破坏有限锚点；任务明确固定提示顺序或玩家自由选择，结合移动攻击与危险窗口 | 锚点身份/受击/两种顺序模式/多目标完成 |
| S1-O-CLEANSE | 净化 | 在若干区域维持清理窗口；受压离开可重新进入，避免一次失误全盘回退 | 区域占用/进度暂停或衰减/完成原子性 |
| S1-O-HUNT | 追猎 | 追踪可见目标，限制其逃逸路线；目标越技术域必须恢复到合法挑战状态，不能无故判玩家失败 | 目标存续/退役/路径可达/逃逸恢复 |
| S1-O-ESCORT | 护送 | 护送自动沿短路线移动的目标；玩家接近才前进，离开停止，失败/恢复与目标HP需独立设计 | 护送实体HP/移动与停靠/阻挡/死亡恢复 |
| S1-O-BOSS | 决战 | 任务指定Boss死亡事实满足目标；不得将任意Boss死亡直接解释为全局或章节通关 | 指定目标的死亡事实/阶段/任务终态优先级 |

目标胜利只交给Mission Objectives判定，再由GameRoot/Settlement提交；不能让Stage内部“任何Boss死亡”提前结束所有任务。玩家死亡、目标死亡和完成同tick优先级须在owner GDD逐类型定义并测试，当前不默认胜利优先。

`13–15分钟`只是标准生存/Boss局的继承目标。破阵、追猎、净化、护送采用主动目标完成，不强加必须等到900秒。任务时限、软硬失败和撤离窗口在系统GDD冻结前均为未定参数。

## 任务生命周期与持久事实（设计输入）

| 状态 | 可执行操作 | 必须持久化或恢复的事实 |
|---|---|---|
| LOCKED | 查看前置与概览 | 前置任务ID，不要求付费/刷取解锁 |
| AVAILABLE | 选角色、备战、开始 | 内容修订、任务ID、角色、已解锁候选 |
| PREPARING | 预检、取消、处理保存不确定态 | 备战消耗与run identity；复用既有reservation设计边界 |
| ACTIVE / PAUSED | 战斗、暂停、保存退出 | 目标进度、局内构筑、RNG、实体/世界状态或已批准检查点 |
| SUSPENDED | 继续本局或明确放弃 | 单个有效run，恢复不重抽、不重复扣除 |
| RESULT_PENDING | 等待提交/处理故障 | 目标结果、首次奖励、解锁和记录必须同次结算提交 |
| COMPLETED | 下一任务、回访/重玩 | 首次完成永久事实；重复完成不能重复解锁奖励 |

这是产品状态语义，不是GameRoot的新枚举；typed字段、字节预算、并发/幂等键、回滚、迁移及旧档映射由ST-S01/ST-S02与Save/Settlement共同设计。已有技术中止与主动放弃规则不可因新增任务被隐式改变。

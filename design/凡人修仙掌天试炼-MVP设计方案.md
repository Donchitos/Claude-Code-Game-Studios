# 《凡人修仙传：掌天试炼》MVP 游戏设计方案

> 项目代号：凡人求生  
> 产品形态：PC 横屏优先、键鼠/手柄操作、俯视角割草生存 Roguelite；移动端竖屏为后续适配形态
> 设计基准：参考《弹壳特攻队》的局内循环，但用“谨慎取舍 + 掌天瓶备战”建立《凡人修仙传》的玩法辨识度  
> 设定依据：用户提供的《凡人修仙传》全设定百科手册  
> 文档性质：当前为内部工作名与跨平台 MVP 基线，不代表正式 IP 设定或最终商业方案；Steam 商业发行前必须完成原创化改名和 IP 清理

---

## 1. 一句话玩法

玩家扮演筑基初期的韩立，在黄枫谷试炼秘境中单手移动、自动御剑，击杀不断涌来的妖兽与魔修，收集灵气构筑功法，在两次“避险或夺宝”的抉择中保存实力，最终击败守阵妖兽并带回灵药。

## 2. 核心设计目标

MVP 只验证三个问题：

1. “移动躲避 + 自动御剑 + 功法进化”的战斗是否爽快；
2. “避险或夺宝”的风险决策是否能体现韩立谨慎、务实、留后手的气质；
3. “掌天瓶催熟灵药 → 下一局携带一项增益”能否形成简单、明确的局外循环。

## 3. 产品定位

| 项目 | MVP 定义 |
|---|---|
| 游戏类型 | Survivor-like + 轻 Roguelite + 修仙题材 |
| 首发平台 | Steam PC，Windows 优先；横屏 |
| 后续平台 | Android、iOS、微信小游戏及其他小游戏运行环境 |
| 操作 | 键盘/鼠标与手柄优先，攻击自动释放；Touch 后续适配 |
| 单局长度 | 12 分钟怪潮 + 最终 Boss，完整一局约 13—15 分钟 |
| 目标玩家 | 喜欢割草、生存、养成和短局 Roguelite 的 PC 玩家；后续扩展移动玩家 |
| 核心爽点 | 飞剑数量增长、剑阵成型、怪潮清屏、险境翻盘 |
| 核心情绪 | 谨慎试探 → 稳步变强 → 留有底牌 → 夺宝脱身 |
| MVP 商业化 | 不接入付费、广告、抽卡和活动系统 |

## 4. 世界观切片

### 4.1 时间与地点

- 时间：韩立筑基初期，已经进入黄枫谷修行；
- 地点：黄枫谷控制的一处小型试炼秘境；
- 事件：秘境禁制异常，妖兽、灵虫和潜入的魔道修士同时出现；
- 目标：韩立需要采得核心灵药，并在秘境崩溃前击败守阵妖兽离开。

该事件为适配玩法而设计的原创支线空间，不绑定小说中的具体战役，从而避免和主要剧情产生直接冲突。

### 4.2 MVP 使用的设定元素

| 设定 | 游戏化用途 |
|---|---|
| 韩立 | 唯一可玩角色 |
| 筑基期 | MVP 战力范围，避免一次覆盖所有修仙境界 |
| 青元剑诀 | 初始攻击和核心进化流派 |
| 长春功 | 恢复及木属性增益 |
| 大衍诀 | 傀儡、神识、暴击和索敌能力 |
| 掌天瓶 | 局外灵药催熟和开局增益 |
| 飞剑、符箓、傀儡 | 主要战斗技能表现 |
| 黄枫谷 | 主界面及任务背景 |
| 魔道修士、妖兽 | 敌人来源 |

### 4.3 暂不使用的设定

- 元婴、化神、灵界、仙界等高阶境界；
- 南宫婉等重要剧情角色；
- 七十二柄完整青竹蜂云剑；
- 玄天之宝、时间法则等后期能力；
- 宗门经营、炼器、拍卖、洞府、道侣和灵兽系统。

原因：这些内容会扩大叙事、美术和系统范围，且会提前消耗后续成长空间。

## 5. 核心玩法循环

### 5.1 局内循环

```text
移动躲避
→ 飞剑和法术自动攻击
→ 击杀敌人掉落灵气
→ 拾取灵气升级
→ 三选一学习或强化功法
→ 主动法术升至五层并满足条件
→ 从精英宝匣中进化为高阶神通
→ 抵抗更强怪潮
→ 击败最终 Boss
```

### 5.2 局外循环

```text
完成试炼
→ 获得灵石、功法残页和灵药种子
→ 使用功法残页进行少量永久强化
→ 用掌天瓶催熟一株灵药
→ 选择下一局携带的丹药增益
→ 再次进入试炼
```

### 5.3 单局体验节奏

| 时间 | 内容 | 设计目的 |
|---:|---|---|
| 0:00—0:30 | 少量低阶灵虫 | 学会移动、自动攻击和拾取 |
| 0:30—2:00 | 普通妖兽逐步增加 | 获得前三次升级，建立基本火力 |
| 2:00—4:00 | 首次密集怪潮 | 检验范围伤害和移动路线 |
| 4:00 | 第一次机缘选择 | 教会“避险或夺宝”机制 |
| 4:00—6:00 | 高速妖兽、远程符修加入 | 迫使玩家走位 |
| 6:00 | 精英：巨甲蜈蚣 | 掉落第一个法宝匣，推动神通进化 |
| 6:00—8:00 | 毒雾区和混合怪潮 | 压缩安全空间 |
| 8:00 | 第二次机缘选择 | 形成最终构筑前的风险决策 |
| 8:00—10:00 | 魔修与妖兽夹击 | 检验清杂和单体输出平衡 |
| 10:00 | 精英：鬼雾修士 | 第二个法宝匣，补全核心神通 |
| 10:00—12:00 | 最终围攻 | 制造满屏火力和临界生存感 |
| 12:00 | Boss：守阵妖兽·碧鳞蟒 | 两阶段最终验证 |

## 6. 玩家操作与战斗规则

### 6.1 基础操作

- 左手或任意触点拖动虚拟摇杆移动；
- 所有攻击和法术自动释放；
- 升级、宝匣和机缘选择时暂停战斗；
- MVP 不设置普攻键、闪避键和主动大招键；
- 暂停界面可以查看当前功法、属性和进化关系。

### 6.2 基础属性

| 属性 | 初始值 | 作用 |
|---|---:|---|
| 生命 | 100 | 降至 0 时本局失败 |
| 攻击 | 10 | 所有攻击的基础伤害 |
| 移速 | 4.5 | 每秒移动距离 |
| 暴击率 | 5% | 默认造成 150% 伤害 |
| 拾取范围 | 1.8 | 自动吸取灵气的半径 |
| 伤害减免 | 0% | 降低受到的最终伤害 |

### 6.3 技能槽位

- 4 个主动法术槽；
- 4 个辅助功法槽；
- 初始青元剑气占用一个主动槽；
- 每个技能最高 5 层；
- 主动技能达到 5 层且拥有对应辅助功法后，可通过精英宝匣进化；
- 已满槽时不再出现新的同类技能，只出现已有技能升级选项。

### 6.4 升级三选一

每次升级从合法候选池中生成三个不同选项：

1. 优先保证前两次升级至少出现一个新主动法术；
2. 已拥有且未满级的技能具有较高权重；
3. 当前主动技能对应的进化功法具有轻微权重加成；
4. 连续两次没有出现可用强化时，第三次触发保底；
5. 每局提供两次免费刷新，避免随机结果直接毁掉一局。

## 7. 功法与法宝技能

MVP 提供 6 个主动技能、6 个辅助功法和 4 个完整进化组合。玩家一局只能持有其中 4+4，保证存在构筑差异。

### 7.1 主动技能

| 技能 | 攻击方式 | 定位 | 五层成长方向 |
|---|---|---|---|
| 青元剑气 | 自动锁定最近敌人发射飞剑 | 初始、稳定单体 | 伤害、飞剑数量、穿透 |
| 火弹术 | 向怪物密集区发射爆炸火球 | 范围清杂 | 爆炸范围、数量、灼烧 |
| 玄铁飞盾 | 法盾围绕玩家旋转 | 近身防御、击退 | 数量、半径、转速 |
| 机关傀儡 | 召唤傀儡自动射击 | 持续输出 | 攻速、持续时间、数量 |
| 雷爆符 | 周期打击随机敌人 | 高伤、对精英 | 雷击数量、伤害、麻痹 |
| 乙木灵藤 | 在玩家周围生成藤刺 | 控制、范围 | 范围、频率、减速 |

### 7.2 辅助功法

| 功法 | 每层效果 | 对应进化 |
|---|---|---|
| 剑诀残页 | 飞剑和投射物伤害 +10% | 青元剑气 |
| 聚灵诀 | 所有技能冷却 -6% | 火弹术 |
| 护体真气 | 受到伤害 -5% | 玄铁飞盾 |
| 大衍神念 | 索敌范围和暴击率提升 | 机关傀儡 |
| 符箓真解 | 范围伤害 +10% | 雷爆符，MVP 暂不制作进化 |
| 长春功 | 每 10 秒恢复少量生命 | 乙木灵藤，MVP 暂不制作进化 |

### 7.3 神通进化

| 五层主动技能 | 所需辅助功法 | 进化结果 | 效果 |
|---|---|---|---|
| 青元剑气 | 剑诀残页 | 小庚剑阵 | 多柄飞剑组成持续旋转剑阵，并自动分出剑光追击 |
| 火弹术 | 聚灵诀 | 连珠火海 | 连续轰炸怪物密集区，残留燃烧区域 |
| 玄铁飞盾 | 护体真气 | 金刚护身阵 | 飞盾持续存在，显著击退近身敌人并周期获得护盾 |
| 机关傀儡 | 大衍神念 | 双傀儡杀阵 | 同时召唤两只常驻傀儡，优先攻击精英和 Boss |

### 7.4 构筑方向

MVP 至少支持三种可通关方向：

1. **剑阵爆发流**：青元剑气 + 雷爆符 + 大衍神念，擅长 Boss；
2. **火海清场流**：火弹术 + 乙木灵藤 + 聚灵诀，擅长怪潮；
3. **护身召唤流**：玄铁飞盾 + 机关傀儡 + 护体真气，容错较高。

任何一种流派都不能同时在清杂、Boss 和生存三个维度最强。

## 8. 《凡人修仙传》差异化机制

## 8.1 机缘：避险或夺宝

在第 4 分钟和第 8 分钟，战斗暂停，出现一次二选一：

### 藏锋避险

- 立即恢复 25% 最大生命；
- 获得持续 10 秒的护身符；
- 不额外生成敌人；
- 奖励稳定但上限较低。

### 冒险夺宝

- 立即生成一只额外精英；
- 精英获得当前阶段 30% 属性强化；
- 击杀后获得法宝匣或大量灵气；
- 若在 45 秒内没有击杀，精英不会消失，并随下一怪潮继续作战。

设计目的：

- 把韩立“判断风险、保存实力、资源最大化”的气质做成实际操作；
- 给高水平玩家主动提高收益的空间；
- 避免所有玩家按照完全相同的时间轴战斗；
- 不增加额外战斗按钮，仍保持单手玩法。

## 8.2 后手：替身符

- 每局默认携带一张替身符；
- 生命首次降至 0 时自动触发；
- 韩立在附近安全位置重新出现，恢复 35% 生命；
- 替身符消耗后本局不可恢复；
- 触发时短暂清除周围普通敌人，但不伤害 Boss。

它既承担一次复活容错，也体现韩立习惯预留保命手段的角色特征。

## 8.3 掌天瓶催熟

每个通过开局预留并进入战斗Loading的run会以等权、无pity规则预抽并持久冻结一个随机灵药种子候选；胜利仅在实际生存43,200..108,000个60Hz Active ticks的合法域内按候选发3枚，正常战败仅在生存到Boss入场线（43,200 ticks，12分钟）时发1枚，主动退出或技术中断不发放。其他结算类型合法生存域为0..108,000 ticks；排除一次性starter后，以交叉乘法验证全域胜利随机种子/Active-minute严格高于eligible战败。正常结算先消费本局预留丹药，再按消费后的库存空间和终身计数空间饱和发奖。首次正常胜利或战败另给三类starter各1枚。下一局开始前，玩家可从已有库存中选择服用其中一株制成的丹药，也可明确选择不服丹；这是胜利偏置、可积累的随机储备，不承诺每局稳定补货：

| 灵药 | 制成丹药 | 下一局效果 |
|---|---|---|
| 凝气草 | 聚气丹 | 开局获得14点等级曲线credit并在首个Active tick前完成普通第1次升级三选一 |
| 铁灵花 | 锻体丹 | 最大生命 +15% |
| 雷元果 | 明心丹 | 暴击率 +8个百分点 |

规则：

- 每局只能携带一种丹药；
- 丹药只在下一局有效；
- 页面默认“不服丹”；无丹确认仍建立唯一可恢复的开局identity，但不改变库存数量；
- 三种种子的`available+reserved`各自上限999；终身earned/consumed只受int64与守恒约束；触顶时奖励显式部分入账或不入账，不能卡死结算/存档；
- MVP 不加入真实时间等待；
- 首次正常胜利或战败成功保存后，额外将三种种子各赠送一个，并与该局随机种子叠加，让玩家能够完整体验系统；
- MVP不把三种种子制作成战场掉落物；Boss线失败结算所获种子同样来自已冻结的结算随机奖；
- 掌天瓶不直接造成伤害，它负责“准备和积累”，保持设定定位。
- 主动退出固定零奖励，但已持久预留的丹药成本必须消费；技术故障只有在sealed补偿结论下才释放预留。

## 9. 敌人设计

### 9.1 普通敌人

| 敌人 | 行为 | 克制需求 |
|---|---|---|
| 噬灵虫 | 数量多，直线追踪，生命低 | 范围伤害 |
| 铁背妖狼 | 移动快，短暂蓄力后冲刺 | 走位、减速 |
| 腐毒妖藤 | 固定在原地，周期喷出毒液 | 远程清除 |
| 甲壳妖虫 | 生命高、抗击退 | 持续伤害 |
| 魔道符修 | 与玩家保持距离并发射符弹 | 穿过怪群主动追击 |
| 血傀儡 | 接近后自爆，死亡有短暂预警 | 及时拉开距离 |

### 9.2 精英敌人

#### 巨甲蜈蚣

- 高生命、高击退抗性；
- 向玩家连续冲刺三次；
- 冲刺结束后进入短暂虚弱；
- 主要检验走位和持续输出。

#### 鬼雾修士

- 周期瞬移到玩家附近；
- 发射扇形魂针；
- 召唤少量血傀儡；
- 主要检验弹幕躲避和目标处理优先级。

### 9.3 最终 Boss：守阵妖兽·碧鳞蟒

#### 第一阶段：100%—50% 生命

- 直线扑咬；
- 扇形毒液；
- 环形毒弹；
- 每次攻击后有清晰后摇。

#### 第二阶段：50%—0% 生命

- 场地外围出现毒雾，逐渐压缩安全区；
- 连续扑咬次数增加；
- 周期召唤噬灵虫；
- 保留明显预警，避免成为纯属性 Boss。

击败后掉落核心灵药并开启离开秘境的传送阵。

## 10. 道具与掉落

| 掉落 | 效果 |
|---|---|
| 灵气微光 | 基础经验 |
| 灵气结晶 | 大量经验 |
| 回春符 | 恢复 30% 最大生命 |
| 引灵符 | 吸取当前场上全部灵气 |
| 爆炎符 | 清除普通敌人并对精英造成固定比例伤害 |
| 法宝匣 | 若满足条件则进化神通，否则随机提升一个未满技能 |

普通敌人主要掉落灵气；恢复和功能道具应保持稀少，避免玩家长期站桩。

## 11. 局外成长

MVP 只保留一棵三分支、每支五级的功法树。

| 分支 | 每级效果 | 满级附加效果 |
|---|---|---|
| 青元剑诀 | 攻击 +3% | 初始青元剑气额外获得一次穿透 |
| 长春功 | 最大生命 +3% | 每局首次低于 30% 生命时恢复 10% 生命 |
| 大衍诀 | 暴击率 +1%、拾取范围 +2% | 每局额外获得一次技能刷新 |

拾取范围按基础值做加法百分比成长：五级大衍诀的上限为 `1.8 × (1 + 5 × 2%) = 1.98`，作为 SpatialGrid 的真实生产查询半径之一，供 workload 与 CELL_SIZE benchmark 使用。查询 buffer 容量由 per-type 最大注册数决定，不由半径推导。

升级资源统一为“功法残页”，不再引入三套独立货币。

设计约束：

- 完成 8—10 局可以升级满一个分支；
- 全部升满不超过 30 局；
- 永久成长只能降低难度，不能替代正确构筑和走位；
- MVP 不制作装备背包、装备品质和随机词条。

## 12. 失败与结算

### 12.1 失败

替身符已经消耗且生命归零时，本局失败。

失败仍可获得：

- 已击杀敌人对应的部分灵石；
- 根据存活时间结算的功法残页；
- 本局Loading已持久冻结的随机灵药种子候选（胜利发3枚；正常战败仅生存满12分钟发1枚；技术中断、主动退出与更早战败不发放）；首次正常结算另给三类starter各1枚。

失败不会完全清空收益，避免 10 分钟后死亡造成过强挫败。

### 12.2 成功

结算展示：

- 存活时间；
- 击杀数量；
- 最终等级；
- 各技能伤害占比；
- 受到伤害来源；
- 是否选择夺宝及夺宝结果；
- 获得的灵石、残页和种子；
- 新纪录。

伤害统计必须展示，否则玩家无法理解构筑效果。

## 14. 数值框架

### 14.1 伤害公式

```text
普通伤害 = 角色攻击 × 技能倍率 × 技能等级修正 × 通用增伤
暴击伤害 = 普通伤害 × 暴击倍率
最终伤害 = 暴击判断后的伤害 × 敌人减伤修正
```

MVP 不引入大量独立乘区，避免数值难以解释。

### 14.2 升级经验

建议初始公式：

```text
升级所需经验 = 8 + 5 × 当前等级 + 0.6 × 当前等级²
```

目标节奏：

- 30 秒内第一次升级；
- 4 分钟前达到 8—10 级；
- 6—8 分钟形成第一个进化神通；
- 通关等级约 28—34 级。

### 14.3 敌人阶段倍率

以分钟为阶段配置，不在代码中写死：

```text
生命倍率 = 1 + 阶段 × 0.18
伤害倍率 = 1 + 阶段 × 0.12
移动倍率 = Min(1.35, 1 + 阶段 × 0.03)
```

实际难度优先通过敌人组合、出怪密度和行为变化调整，不应只堆生命值。

## 15. 技术实现方案

### 15.1 推荐技术栈

- 引擎：Godot 4.7.1（项目权威配置以根目录 `CLAUDE.md` 与 `.claude/docs/technical-preferences.md` 为准；旧 Unity 建议已被取代）；
- 语言：GDScript；若 SpatialGrid 真机 spike 连续不满足已批准子预算，再通过 ADR 评估 GDExtension，不预先引入原生扩展；
- 表现：2D 俯视角，角色和怪物使用序列帧或骨骼动画；
- 配置：Godot `Resource`（`.tres`）为运行时权威格式，可由 CSV/JSON 导入生成；
- 存档：MVP 使用本地存档；
- 服务端：MVP 不接入；
- 随机：每局生成随机种子，便于复现问题。

### 15.2 客户端模块

```text
GameRoot
├── InputSystem
├── PlayerController
├── WeaponSystem
├── ProjectileSystem
├── EnemySystem
├── SpawnDirector
├── SpatialGrid
├── DamageSystem
├── DropSystem
├── SkillDraftSystem
├── BuffSystem
├── RiskChoiceSystem
├── BossStateMachine
├── BattleUI
├── SettlementSystem
└── SaveSystem
```

### 15.3 数据配置

至少包含：

- `StageConfig`：地图、时长、阶段和奖励；
- `WaveConfig`：出怪时间、速率和数量上限；
- `EnemyConfig`：属性、行为类型和掉落；
- `SkillConfig`：等级参数、效果和进化关系；
- `ProjectileConfig`：速度、范围、穿透和命中规则；
- `BuffConfig`：增益类型、数值和持续时间；
- `DropConfig`：掉落权重；
- `ProgressionConfig`：功法树和消耗；
- `HerbConfig`：种子、丹药和开局效果。

### 15.4 同屏性能

MVP 目标不是宣传意义上的千怪同屏，而是稳定支持：

- 300 个活跃普通敌人；
- 400 个投射物或攻击对象；
- 300 个地面掉落物；
- 中端 Android 设备平均 50 FPS 以上，目标 60 FPS。

实现要求：

1. 敌人、投射物、掉落物和伤害数字全部对象池化；
2. 普通敌人不使用完整寻路，只朝玩家移动；
3. 敌人之间不做高成本刚体碰撞，使用轻量分离；
4. 使用空间网格查询附近敌人，范围攻击不得遍历全场；
5. 伤害数字按目标和时间窗口合并；
6. 屏幕外敌人降低动画和行为更新频率；
7. 特效设置数量上限和降级方案；
8. 不建议 MVP 直接采用完整 ECS，普通对象池和批量更新足以验证玩法。

### 15.5 敌人行为

普通追踪敌人：

```text
方向 = Normalize(玩家位置 - 敌人位置)
位移 = 方向 × 移动速度 × DeltaTime
```

精英和 Boss 使用有限状态机：

```text
追踪
→ 技能预警
→ 释放技能
→ 后摇
→ 重新追踪
→ 阶段切换
→ 死亡
```

### 15.6 技能系统

技能效果应由公共组件组合：

- 自动索敌；
- 直线投射物；
- 环绕物；
- 范围爆炸；
- 持续伤害区；
- 召唤物；
- 链式或随机打击；
- 击退、减速、灼烧和护盾。

避免每个技能编写一套独立框架。技能配置只决定组件组合和参数。

### 16.1 美术资产

| 类型 | MVP 数量 |
|---|---:|
| 韩立角色 | 1 套，待机/移动/受击/死亡 |
| 普通敌人 | 6 种 |
| 精英 | 2 种 |
| Boss | 1 种、2 阶段表现 |
| 主动技能 | 6 套特效 |
| 进化神通 | 4 套强化特效 |
| 地图 | 1 张固定竞技场；MVP 不做循环拼接或世界坐标回绕 |
| UI 页面 | 4 个 |
| 图标 | 约 30 个 |

### 16.2 美术方向

- 角色采用易识别的国风 Q 版比例；
- 法术颜色保持功能区分：剑气青、火术赤、护盾金、神识紫、木术绿；
- 敌方投射物必须与己方特效明显区分；
- Boss 技能优先保证预警可读性；
- 后期满屏技能仍需看清角色、危险区域和掉落物。

### 16.3 音频

- 普通击杀音效保持轻而密；
- 精英和 Boss 命中使用更重反馈；
- 神通进化提供独立音效和短暂演出；
- 低生命时增加克制的心跳或灵力紊乱提示；
- 替身符触发必须形成清晰的“保命成功”反馈。

## 17. 新手引导

首局采用无文字或短句引导：

1. “拖动以移动”；
2. “飞剑会自动攻击”；
3. “拾取灵气可以提升修为”；
4. 第一次升级时说明三选一；
5. 第一次拥有匹配功法时，在技能卡标记“可进化”；
6. 第 4 分钟说明避险与夺宝的收益和风险；
7. 首次失败后介绍替身符；
8. 首局结算后解锁掌天瓶。

禁止连续弹出多个系统说明。

| 指标 | 目标 |
|---|---:|

## 19. 开发任务拆分

### 阶段一：灰盒战斗，1 周

- 移动和摄像机；
- 自动飞剑；
- 一种普通敌人；

### 阶段二：完整局内垂直切片，2 周

- 6 个主动技能；
- 6 个辅助功法；
- 4 个进化神通；
- 6 种普通敌人；

- 机缘二选一；

- 12 分钟时间轴。

### 阶段三：Boss 与局外循环，1—2 周

- 碧鳞蟒两阶段战斗；
- 结算和伤害统计；
- 三分支功法树；
- 掌天瓶和三种丹药；

- 首页、准备页和结算页。

### 阶段四：表现与测试，1 周

- 正式或半正式美术替换；
- 技能、命中、受击和清屏反馈；
- 性能优化；
- 新手引导；
- 数值调优；
- 设备兼容性和异常恢复测试。

建议开发周期：4—6 周。建议最小团队为 1 名客户端、1 名兼任策划的制作人、1 名 2D 美术；音频可以使用资源库或外包。

## 21. 主要风险与控制方式

| 风险 | 表现 | MVP 控制方式 |
|---|---|---|
| 只像换皮《弹壳特攻队》 | 除名称和美术外没有差异 | 保留机缘选择、替身符和掌天瓶备战 |
| 修仙设定过大 | 一开始覆盖多境界和大量系统 | 只做筑基初期的一次秘境试炼 |
| 技能只有一个最优解 | 所有人固定选择剑阵 | 保证三种构筑均能通关并各有短板 |
| 数值压过操作 | 战力不足必然失败 | 永久成长幅度受控，Boss 技能可躲避 |
| 怪多导致卡顿 | 中低端手机掉帧 | 300 怪目标、对象池、空间网格、特效降级 |
| 视觉过载 | 看不清角色和敌方攻击 | 己方特效降亮度，危险预警保持最高层级 |
| IP 设定争议 | 原创支线与原作冲突 | 使用非关键时间点和原创秘境，不改写主要人物关系 |
| 商业授权 | 使用正式角色和名称存在权利要求 | 商业发布前必须获得合法 IP 授权 |

## 22. MVP 完成定义

满足以下条件，才算完成，而不是“已经能跑”：

1. 新玩家无需阅读长教程即可在 30 秒内理解移动、攻击和升级；
2. 一局从开始到 Boss 结算完整可玩；
3. 三套主要构筑都能通关，且操作感受明显不同；
4. 两次机缘选择不存在长期必选答案；
5. 替身符能制造一次明确但不过度的翻盘；
6. 掌天瓶能够影响下一局选择，但不会强迫玩家等待；
7. 失败后玩家能够理解主要死亡原因；
8. 目标设备在最高压力阶段仍保持可接受帧率；
9. 所有关卡、敌人和技能关键数值可以通过配置调整；
10. 功法树全部升级后，战斗仍需要构筑和走位，而不是自动通关。

## 23. 后续版本方向

只有 MVP 数据和试玩反馈成立后，再按以下顺序扩展：

1. 第二角色或第二套初始功法；
2. 第二地图与不同环境规则；
3. 法器选择和少量装备构筑；
4. 炼气至筑基的境界突破章节；
5. 更多机缘事件和撤退结算；
6. 宗门委托和周期挑战；
7. 轻量活动；
8. 最后再评估商业化和联网能力。

后续版本仍应坚持一个原则：新增系统必须带来新的战斗决策或风险选择，不能只增加新的战力乘区。

# Claude Code Game Studios 初学者学习课程

这套课程面向第一次接触 Claude Code 项目级配置、技能（Skill）、智能体（Agent）和生命周期 Hook 的读者。目标不是背下 73 个命令，而是理解这套框架如何把“一个 AI 对话”组织成可追踪、可审查、可持续推进的游戏开发流程。

## 课程基线

- 分析版本：仓库标签 `v1.0.0`
- 核心规模：49 个 Agent、73 个 Skill、12 个 Hook、11 条路径规则、40 个实际模板文件
- 主要运行环境：Claude Code；Hook 使用 Bash，Windows 上建议使用 Git Bash
- 项目性质：这是“游戏开发协作模板”，不是一个可编译运行的游戏

`src/` 和 `production/` 目前几乎为空是正常的：它们是使用模板后逐步产生游戏代码和生产资料的位置。真正的框架实现集中在隐藏目录 `.claude/`。

## 贯穿课程的练习项目

课程使用一个极小的 2D 游戏概念“闪避方块”作为练习：玩家移动一个方块，躲避不断出现的障碍，坚持 60 秒即获胜。它有意保持简单，让注意力集中在框架，而不是游戏制作本身。

建议在仓库副本或新分支上做练习：

```bash
git switch -c codex/ccgs-course
```

部分命令会创建或修改 `design/`、`docs/architecture/`、`production/` 等目录中的文件。开始每个实验前运行 `git status --short`，结束后检查 `git diff`，不要在有重要未提交修改的工作区中练习。

## 学习方法

每课都按四步进行：

1. 先回答“这个组件解决什么问题”。
2. 再从仓库读取一个真实文件。
3. 画出或口述输入、处理、输出。
4. 用课末检查题验证自己是否真的理解。

当文档与代码描述不一致时，以实际配置和实现文件为准，并把差异记录下来。这个习惯本身就是维护此类提示词框架的重要能力。

## 最终能力标准

完成课程后，你应该能够：

- 在 5 分钟内判断一个需求应使用 Skill、直接 Agent，还是 Hook/Rule；
- 沿着文件路径解释一次 `/dev-story` 如何获得设计、架构和测试上下文；
- 修改一个 Skill 时同步更新参考文档、测试规格和目录登记；
- 识别自动检查、人工决策和模型判断三者的边界；
- 为自己的游戏裁剪 Agent、Skill、评审模式和模板，而不破坏可追踪链。

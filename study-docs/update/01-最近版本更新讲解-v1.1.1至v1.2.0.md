## v1.1.1（2026-09-24）：技能为什么一启动就"夭折"

### 问题

v1.1.0 引入了统一的 `project.yaml` 配置。为了读取配置，几乎每个技能开头都会跑一段 shell 命令。问题出在写法上：命令里带有 `$(...)` 这类展开（expansion）。

Claude Code 在项目默认的 `default` 权限模式下，会拒绝"含展开"的 shell 命令，除非用户显式批准。结果是：

- **74 个技能里有 66 个，一启动就中止**，还没做任何事；
- 从项目的任何子目录启动都一样；
- 即使用 auto 模式、或由 Claude 自主调用，也会被卡住；
- `game-designer` 和 `creative-director` 因为预加载了技能，**启动即失败**。

这是一个"框架自己把自己绊倒"的典型故障：设计意图没问题，但实现方式撞上了权限模型。

### 改动

- 每个技能把配置查询改成**一条普通命令**，不再含展开；
- 在技能自己的 frontmatter 里**只预批准这一条命令**，其它什么都不批准；
- 技能从任意子目录都能找到项目的 `project.yaml`；
- `/changelog` 在没有提交记录的新仓库里也能用。

### 提升

- 技能在**所有权限模式**下都能正常启动；
- 项目根目录、`src/`、`design/` 等子目录启动都可用；
- 预批准范围从"一大片"缩到"一条命令"，顺手把安全边界也收紧了。

> 这一版没有加新功能，但它决定了后面所有功能"能不能被用上"。

## v1.1.2（2026-09-29）：默认路径走通，三引擎平权，检查说真话

这一版是 1.1.1 的修复版，官方说法是"每个 bug 都先复现再修"。它分四个主题。

### 1）默认的 `minimal` 路径不再是死路

**问题**

框架的默认流程是 `rigor: minimal`，但很多地方仍按 `standard` 写：

- minimal 下没人运行 `/gate-check`，阶段就永远不动；`/help` 把它误判成 Concept 阶段，于是向一个已经有 brief 和三个故事的项目要概念文档、美术圣经、系统图；
- 十几个技能在 minimal 下只会说"去跑 `/sprint-plan`"，可 minimal 根本没有 sprint；
- 文档里约 25 处把 `standard` 的值当成默认值；
- 十个技能只认概念文档，不认 minimal 用的 `design/game-brief.md`。

**改动**

- `/help`、`/story-done`、状态行都改为沿 minimal 路线走：**选引擎 → 写 brief → 建故事 → `/dev-story` ↔ `/story-done`**；
- 状态行显示成 `Minimal · 1/3 stories` 这种形式；
- 所有"去开 sprint"的死路改成 minimal 的下一步；
- 修正默认值表述：默认是 `minimal`，对应 `coarse` 故事、`terse` 文档、`solo` 评审；
- 只读概念文档的技能，同时读 `design/game-brief.md`；
- 会话检查点写入 `production/session-state/active.md`，下次会话真的能看到；
- 新增 [story-status.sh](file:///workspace/.claude/scripts/story-status.sh)，统一故事排序：先关 `In Review`，再继续 `In Progress`，然后按构建顺序取下一个。

**提升**

- 新项目走默认配置就能**端到端跑通**，不再"每一步都被建议去开 sprint"；
- 用户中断后回来，能接着上次的位置继续；
- 三个入口（`/help`、`/story-done`、`/sprint-status`）对"下一个该做哪个故事"给出**同一个答案**。

### 2）Unity 和 Unreal 终于得到和 Godot 同等的照顾

**问题**

测试命令看起来能跑，实际不可信：

- **Godot**：`/setup-engine` 写的测试命令加载了一个 gdUnit4 根本没发布的 runner，所以每次都失败；`/dev-story` 的语法检查在解析错误时也返回 0；
- **Unity**：测试放在 `tests/`，而 Unity 根本不编译这个目录，于是"0 个测试，通过"；编辑器用裸 `Unity` 可能调到另一个 CLI；上一次的结果文件会被当成本次结果；
- **Unreal**：`qa-tester` 模板用了不存在的参数，测试放在 `Source/Tests/`（从不参与构建）；全新 checkout 没有编译好的游戏模块，编辑器在跑测试前就退出；命令用相对 `.uproject`，UE 5.7 找不到；测试失败和"没匹配到测试"都返回 255，无法区分。

**改动**

- Godot 换成 gdUnit4 官方 runner，加参数避免脚本错误卡在 `debug>`；新增 [godot-parse-check.gd](file:///workspace/.claude/scripts/godot-parse-check.gd) 逐个加载改动脚本；
- Unity 测试移到 `Assets/Tests/`，编辑器写全路径，编译错误判 FAIL，只读本次结果文件；
- Unreal 先构建 editor target，CI 明确要求 Windows self-hosted runner，命令全部用绝对路径，`/smoke-check` 读输出区分"失败"和"没匹配到"；
- `/smoke-check` 先跑测试，**没跑成就报 NOT ASSESSED**，而不是当作通过；
- 三个引擎的测试输出按各自格式解析（Unreal `Result={…}`、Unity NUnit `<test-case>`、gdUnit4 `reports/`）；
- 编码规则、数据校验、技术债、发布清单扩展到 `Assets/` 和 `Source/`；
- Unreal 补上 Linux/macOS 命令。

**提升**

- "测试通过"这句话**第一次真的可信**；
- 没运行、没匹配、被跳过的情况会明确说 **NOT ASSESSED**，不再伪装成 pass；
- Unity/Unreal 项目不再是"二等公民"。

### 3）检查与 Hook：从"静默"变成"看得见"

**问题**

提交检查、推送检查、资源检查、技能改动检查都会产生警告，但这些警告打印在**用户和 Claude 都看不到的地方**——等于没检查。

**改动**

- 警告同时显示在终端并送达 Claude；
- 提交检查覆盖链式命令：`git add -A && git commit`、`git -C . commit`、`if git commit`、`bash -c "git commit"`、`sudo`、`xargs`、Windows 路径等；
- **here-doc 里的文字不再被当成命令**，避免文档里提到 `git push` 就误报；
- 校验的是 **staged 副本**，不是磁盘上的文件；支持 `.JSON`、UTF-8 BOM、非 ASCII 文件名；
- PowerShell 工具也套用危险命令 deny 规则；
- 会话启动把过长的检查点截到 25 行并先打印警告（因为 hook 输出超过 10,000 字符后，Claude 只能看到 2,000 字符预览）；
- 推送告警保护 `main`、`master`、`release/*`，不再误报 `develop`。

**提升**

- 检查从"心理安慰"变成**可执行的反馈**；
- 危险操作（force push、`reset --hard`、递归删除）在 PowerShell 里也拦得住。

### 4）技能与智能体：文档和实际行为对齐

**问题**

技能规格（spec）大量过期：一次完整 `/skill-test spec` 跑下来，**121 个 spec 全失败**。有的在等一个技能从来没说过的词（比如 `/help` 的 "HELP COMPLETE"）；36/49 个智能体 spec 写的模型根本不是智能体声明的模型。

另外：

- 总监被要求对所有门禁回答 `APPROVE / CONCERNS / REJECT`，但 8 个门禁有自己的判词（如 `ON TRACK / AT RISK / OFF TRACK`），技能按自己的词判断，导致 `/milestone-review` 永远看不到 `OFF TRACK`；
- 三位总监把记忆存在用户主目录，**同一台机器上的所有项目共享**；
- `devops-engineer` 写的是 GitFlow，而项目约定是 trunk-based；
- 不写代码的智能体（`qa-lead`、`writer` 等）还在问"静态工具类还是场景节点？"。

**改动**

- 121 个 spec 按当前技能/智能体重写；
- 模型档位统一写成别名 `opus / sonnet / haiku / inherit`，不写具体模型 ID；
- 总监从门禁定义文件里读取该门禁自己的判词；
- 三位总监的记忆迁到项目内 `.claude/agent-memory/`（已被 gitignore）；
- `devops-engineer` 改为 trunk-based；
- 非编程智能体改为"起草 → 提议 → 询问"。

**提升**

- 测试规格重新**能证明东西**；
- 门禁判词不再"鸡同鸭讲"；
- 项目记忆隔离，换项目不串味。

## v1.1.3（2026-10-08）：长会话不断片，没回答不算回答

### 问题一：长技能在压缩后"后半段消失"

Claude Code 在上下文压缩（compaction）后，只会重新挂载被调用技能的**前半部分**。于是长技能的后几个阶段会在会话中途悄悄丢掉——不是报错，是"做着做着就没了"。

### 改动

- 14 个最长技能把每个阶段拆进自己的 `references/` 文件，阶段开始时读一次，压缩后再读一次：
  `/adopt`、`/architecture-decision`、`/architecture-review`、`/create-architecture`、`/design-system`、`/dev-story`、`/gate-check`、`/prototype`、`/review-all-gdds`、`/setup-engine`、`/smoke-check`、`/story-done`、`/test-setup`、`/ux-design`；
- **步骤本身不变**，只是换了存放位置；
- 引用文件按技能目录相对命名，装到哪里都能找到；
- 超过 100 行的引用文件开头列出目录；
- `/skill-test` 和 `/skill-improve` 也会读这些文件，判断"整个技能"而不是只看主文件。

### 提升

- 长流程在长会话里**保持完整**；
- 修复可以落到真正持有那段文字的文件里。

### 问题二：跳过、关掉、空回答，被当成"同意"

### 改动

- 任何模式下，**被跳过、被关闭、返回空**的问题都不算回答：不写入、不设置、不选择，并用纯文本再问一次；
- guided 模式自相矛盾的地方修正：新文件等 "May I write?"，已有文件的更新在简短摘要后继续；
- 14 个智能体不再使用它们没有的提问工具，改为返回一个简短选项列表，由技能来问。

### 提升

- "没人回答"不再产生**莫须有的配置或文件**；
- 智能体不会因为工具不存在而卡住。

### 问题三：权限比想象中宽

### 改动

- 四条 allow 规则在 `*` 前**少了一个空格**，于是匹配命令名后的任意文本：`git branch -D` / `-m`、`git log --output=<file>`、`git diff --output=<file>`、`python -m json.tool <in> <out>` 都能不询问直接跑（auto 模式下还会跳过分类器）。这些规则被删除；
- 只读 git 命令（`git status`、`git log`）仍然免询问；
- `.env` 文件禁止 Edit；
- 明确要求：**从项目根目录启动 Claude Code**。因为 `.claude/settings.json` 只从启动目录加载，在 `src/` 启动会丢失 hooks、deny 规则和 ask-first 模式。

### 其它修复

- 从子目录读取设置时回到项目根；
- 提交检查能看见同一条命令里先 `git add` 再 `git commit` 的文件；支持"项目是大仓库子目录"和 Git LFS 中的 JSON；
- Unreal 版本检查读 `Build.version`，不再运行会打开编辑器且永不返回的 `UnrealEditor-Cmd -version`；
- 注册表查询改成精确匹配（问 `combat` 不再命中 `combat-ai`）；
- `/start` 只写一个 `modes:` 块；
- 每个技能都有标题。

### 提升

- 权限边界**可解释、可复现**；
- 子目录、LFS、Windows 换行等"边角环境"不再悄悄出错。

## v1.2.0（2026-10-19）：最大的一版

官方摘要：**故事类技能围绕共享辅助脚本重建；读取守卫阻止整文件读取大型设计文档；引擎参考升级到 Godot 4.7 和 Unreal Engine 5.8；不再有任何技能预批准所有 shell 命令。**

这是四个版本里信息量最大的一版，下面按主题讲。

### 1）六个故事技能按 Anthropic 的技能编写指南重构

**涉及**：`/create-stories`、`/story-readiness`、`/create-epics`、`/dev-story`、`/story-done`、`/start`。

**做法**

- 主路径留在 `SKILL.md`，**罕见分支移到 `references/`**，固定步骤交给脚本；
- `/start` 保持单文件，从你的描述**推断 rigor**，把 rigor 和阶段放在一张卡片上，只问一次"存不存"；
- `/create-stories` 起草前先报每个管辖 ADR 的状态；如果故事依赖的 ADR 还没 Accepted，就**挡住**这个故事；
- `/create-epics` 会标记"唯一 ADR 还是 Proposed"的需求，让上面的拦截继续有效；
- `/dev-story` 把每个代码故事改动的文件交给对应引擎专家；brief 明确禁止一次性 helper、为不可能发生的错误写处理、为了让测试过而特判的值；
- `/story-done` 的报告有一行 **Reviewed by**，永远不会空着：`lead-programmer`、`/code-review（你说你跑过，这里未验证）` 或 `self, no independent review`；
- `/brainstorm` 只在 `standard` 和 `full` 下加载完整概念流程。

**为什么**

长技能把所有分支都塞在主文件里，既费上下文，又让模型在长文里"迷路"。Anthropic 的技能编写建议是：**主路径短、分支按需加载、固定步骤脚本化**。

**提升**

- 技能更容易被正确执行，也更省上下文；
- 故事的范围、依赖、评审责任都**有明确落点**；
- `/story-done` 不会再用一个空白字段假装"有人评审过"。

### 2）读取守卫：不许再"一口吞下"大设计文档

**新增** [validate-read.sh](file:///workspace/.claude/hooks/validate-read.sh)，配合 [read-guard.sh](file:///workspace/.claude/scripts/read-guard.sh)。

**规则**

- 对 `design/`、`docs/architecture/`、`production/session-state/` 下**超过 40 KB** 的文档，拒绝整文件读取；
- 拒绝时**返回按行号排列的标题**，让重试直接读某一节；
- **带范围的读取（offset + limit）永远放行**；
- 配置项：`features.read_guard: off`（或 `false`）关闭，`features.read_guard_kb` 改阈值；
- 优先级链：`project.local.yaml` → `project.yaml` → 默认 40 KB；
- 协作规则第 6 条改为"按节读设计文档"，大多数读 GDD / ADR / 美术圣经的技能也改成按节读。

**为什么**

读一份 100 KB 的 GDD，会把大量**与当前任务无关的内容**塞进上下文，既贵又挤掉真正的工作空间。更糟的是用固定大小的 `grep` 截取长章节，会**截断内容**。

**提升**

- 上下文成本可控；
- 模型先看到"目录"，再决定读哪一节，定位更准；
- 读取不再被静默截断。

### 3）辅助脚本：把"每次都要重新想一遍"的固定步骤沉淀下来

**规模**：`.claude/scripts/` 新增 25 个脚本、修改 7 个，当前共 35 个。

**它们回答的问题**

| 类别 | 代表脚本 | 回答什么 |
|------|---------|---------|
| 故事 | [story-facts.sh](file:///workspace/.claude/scripts/story-facts.sh)、[story-status.sh](file:///workspace/.claude/scripts/story-status.sh) | 故事事实、按顺序列出故事 |
| 架构 | [adr-status.sh](file:///workspace/.claude/scripts/adr-status.sh)、[adr-dep-graph.sh](file:///workspace/.claude/scripts/adr-dep-graph.sh) | ADR 状态、依赖图与构建顺序 |
| Markdown | [md-section.sh](file:///workspace/.claude/scripts/md-section.sh) | 取一节到下一个标题为止 |
| 项目状态 | [project-state.sh](file:///workspace/.claude/scripts/project-state.sh)、[set-stage.sh](file:///workspace/.claude/scripts/set-stage.sh) | 当前阶段、写阶段 |
| 会话 | [session-state.sh](file:///workspace/.claude/scripts/session-state.sh)、[rotate-session-state.sh](file:///workspace/.claude/scripts/rotate-session-state.sh) | 检查点读写与轮转 |
| 配置 | [config-set.sh](file:///workspace/.claude/scripts/config-set.sh) | 安全写配置 |
| 守卫 | [read-guard.sh](file:///workspace/.claude/scripts/read-guard.sh)、[write-guard.sh](file:///workspace/.claude/scripts/write-guard.sh) | 读写边界判断 |
| 度量 | [bug-stats.sh](file:///workspace/.claude/scripts/bug-stats.sh)、[code-markers.sh](file:///workspace/.claude/scripts/code-markers.sh)、[debt-register.sh](file:///workspace/.claude/scripts/debt-register.sh)、[flaky-stats.sh](file:///workspace/.claude/scripts/flaky-stats.sh) | Bug 数、代码标记、技术债、flaky 率 |
| 规划 | [plan-math.sh](file:///workspace/.claude/scripts/plan-math.sh) | sprint 算术 |
| 资源/内容 | [asset-scan.sh](file:///workspace/.claude/scripts/asset-scan.sh)、[content-count.sh](file:///workspace/.claude/scripts/content-count.sh) | 资源检查、内容统计 |
| 测试 | [test-run.sh](file:///workspace/.claude/scripts/test-run.sh)、[test-scaffold.sh](file:///workspace/.claude/scripts/test-scaffold.sh) | 跑测试、搭测试骨架 |
| 注册表 | [registry.sh](file:///workspace/.claude/scripts/registry.sh) | 列出、查找、校验、发下一个 ID |

**设计约束**

- 每个脚本输出的是**观察，不是裁决**；
- 都有 `--help`；
- 除 `agent-check.sh` 和 `compat-inventory.sh` 需要 Python 3 外，其余只需要 bash + awk。

**为什么**

同一类问题以前由技能"每次手算"：不同时间、不同措辞可能得到不同答案；用 grep 取章节还可能被截断。**脚本把确定性下沉**，模型负责判断，不负责重复计算。

**提升**

- 同一个问题**每次得到同一个答案**；
- 长章节不会被固定大小截断；
- 技能主文件更短，维护点更集中。

### 4）证据知道自己的代码变了没有

**新增**：`/dev-story` 在故事保留的截图旁写 `stamp.txt`，记录这些截图证明了哪些文件。

**行为**

- `/story-done` 和 `/test-evidence-review` 会点名"截图之后又改过的文件"，并提示 **re-capture it**；
- 老证据没有 stamp，就明确说 **no stamp**；
- **只报告，不阻塞**。

**为什么**

截图是最容易"过期"的证据：代码改了，旧截图还躺在那里，看起来一切正常。时间戳把"证据"和"被证明的代码"绑在一起。

**提升**

- 评审时能看出证据是否仍然有效；
- 不会用一张过期截图关闭故事。

### 5）故事终于列出自己的文件

**新增模板** [story.md](file:///workspace/.claude/docs/templates/story.md)，包含 `## Files` 段。

**流程**

- `/create-stories` 列出**计划**要改的文件；
- `/dev-story` 用**实际**改动的文件替换它；
- `/story-done` 拿实际范围对照计划范围。

**为什么**

旧版 `/story-done` 的范围检查会去找一个"没有任何故事拥有"的文件列表，所以这项检查**根本跑不起来**。

**提升**

- 范围蔓延（scope creep）有了可检查的基准；
- 故事的计划与实际改动**有据可查**。

### 6）注册表：ID 永不复用

**新增** [registry.sh](file:///workspace/.claude/scripts/registry.sh) 和 [validate-registry.sh](file:///workspace/.claude/hooks/validate-registry.sh)。

- `registry.sh` 支持列出、查找、校验三个注册表；下一个 ID = **历史最高值 + 1**，所以退役的 ID 不会被复用；
- 它还能读出 1.1.3 的 `/architecture-decision` 写下的未加引号 `status: superseded_by:` 行，并逐条提示去加引号；
- `validate-registry.sh` 在写入实体注册表或 TR-ID 注册表时，如果会**删除、重编号**条目，或写入表头没列出的状态，就发出警告；
- 写注册表的技能在写完后会自行校验。

**提升**

- 需求 ID、实体 ID 稳定，历史引用不会突然指向别的东西；
- 注册表结构不容易被一次误写破坏。

### 7）写入守卫：警告，但不拦路

- [validate-write.sh](file:///workspace/.claude/hooks/validate-write.sh)：当写入会覆盖"技能永不覆盖"的文件（已存在的 `EPIC.md`、`project.godot`、引擎参考文档）、把配置设成列表外的值、越过原型边界、或破坏本地化冻结时，发出警告；
- [validate-agent-artifact.sh](file:///workspace/.claude/hooks/validate-agent-artifact.sh)：子智能体结束时没写 brief 指定的文件，就告诉你。

**设计意图**：这类问题**值得提醒，但不值得一刀切阻塞**。守卫负责"让你看见"，决定权仍在你。

### 8）安全：从"预批准一切"到"只批准自己跑的那条"

**问题**

技能 frontmatter 里一个裸 `Bash` 条目，会让 **34 个技能**在默认权限模式下运行任意 shell 命令而无需询问。这等于把整个项目的权限交给了技能文本。

**改动**

- 34 个技能改为**逐一列出**自己真正会跑的框架脚本和只读命令；
- 其它命令（包括你的 `commands.test`）**先询问**：批准一次，或把 `Bash(<你的命令> *)` 加到 `.claude/settings.local.json`；
- 推送检查新增告警：`git tag`、`git merge`、`gh release`、`butler push`、`steamcmd +run_app_build`；
- 三条 Bash `.env` 规则删除（`Read(**/.env*)` 和 `Edit(**/.env*)` 已经覆盖 Bash 文件命令和重定向）；
- `settings-local-template.md` 不再建议 `Bash(git *)`（它会连 `git push` 一起批准）；
- 协作规则第 7 条：**智能体永不上游提 issue / PR**，只写草稿给你提交；
- `settings.json` 拒绝 `Edit(**/*.uasset)` 和 `Edit(**/*.umap)`，防止把 Unreal 二进制资源当文本改坏。

**提升**

- 权限从"技能说它能跑什么"变成"技能说它**实际**跑什么"；
- 发布、打标签、合并、上传商店这些高风险动作**先被提示**；
- 二进制资产不会被手滑改坏。

### 9）引擎参考：Godot 4.7、Unreal 5.8、Unity 6.3 LTS

- **Godot**：从 4.6 升到 **4.7**（最新补丁 4.7.2），覆盖 AreaLight3D、HDR 输出、Asset Store、VirtualJoystick、Jolt 变化、typed-return override；见 [VERSION.md](file:///workspace/docs/engine-reference/godot/VERSION.md)；
- **Unreal**：从 5.7 升到 **5.8**（最新 hotfix 5.8.3），记录 breaking changes、废弃 API、模块和插件；当 5.8 编辑器与 Epic release notes 不一致时，参考文档会**明确指出**（如 MegaLights 仍标 Experimental、Iris 仍带 Beta）；
- **Unity**：保持 **6.3 LTS**，并列出 6.4–6.6 与 6.7 beta 为"更新但 API 未确认"；
- 如果你要留在 Godot 4.6 或 Unreal 5.7，**保留原来的引擎目录即可**；
- CI 模板升级到 `actions/checkout@v7`、`actions/upload-artifact@v7`（自托管 runner 需 2.327.1+），Godot 4.7.2 + gdUnit4 6.2；
- Godot 4.7 新项目首次导入若以 139 退出（导入完成后退出崩溃），`/setup-engine` 会再跑一次导入。

**提升**

- 引擎专家建议的 API 与当前版本对齐，减少"照文档写出不存在的 API"；
- 升级路径明确：要么跟着升级，要么保留旧目录。

### 10）工作树：从"你的提交"开始，并带上本地配置

- `settings.json` 设置 `worktree.baseRef: "head"`，工作树从**你当前的提交**开始，而不是远端默认分支；
- 新增 [.worktreeinclude](file:///workspace/.worktreeinclude)，把 `project.local.yaml`、`CLAUDE.local.md`、`.claude/settings.local.json` 复制进每个工作树；
- `.gitignore` 忽略 `.claude/worktrees/`；
- 原型技能会说明：工作树看不见的未提交文件、需要你先提交的文件、Git LFS 拉取、以及哪些检查它跑不了。

**为什么**

旧行为下，原型或隔离子智能体拿到的是"远端 main"，**没有你本地刚写的提交**，于是它看到的世界和你的不一样。

**提升**

- 工作树里的代码和配置与当前会话一致；
- 不会再出现"我这里明明有，它那里没有"。

### 11）没用的 Hook 停掉，该异步的异步

- 删除 `post-compact.sh`：Claude Code 会丢弃它的输出，而 `session-start.sh` 已经负责恢复上下文；
- Stop hook 改为后台运行，不再拖住一轮对话；
- `notify.sh` 只在权限询问和空闲提示时触发。

**提升**

- 少跑无用逻辑，少占一轮时间；
- 通知不再打扰无关场景。

### 12）门禁与评审：不再"假通过"

这一版修了很多"看起来通过了，其实没检查"的问题：

| 问题 | 修复 |
|------|------|
| `/architecture-review` 在引擎升级、注册表/架构/预算变化后仍复用旧报告 | 校验它读过的**每个文件**，点名被删除的 GDD/ADR，不允许用更窄的报告冒充完整报告 |
| `/architecture-review single-gdd` 会覆盖全项目追溯索引 | 只写该系统的内容 |
| ADR 没有 `Layer` 行，导致所有 ADR 都被算成 critical | `/architecture-decision` 写 Layer 行；`superseded` 状态按 YAML 要求加引号 |
| 重跑 `/create-architecture` 会重编号 TR-ID | 保留已注册 ID，新 ID 标 provisional |
| `/design-review` 只查注册表本身 | 检查 GDD 表格里**每一处**重复值，矛盾项带行号阻塞 |
| `/story-readiness` 对 `fine` 粒度也硬要 3 条验收标准 | 按 `story_granularity` 决定条数（coarse 3/2/1、balanced 2/2/1、fine 1） |
| 门禁有 concern、但必需检查没跑，仍可接受并推进阶段 | 未跑完必需检查前**不提供 override**，报告点名缺哪项 |
| 局部检查被当成完整检查 | `/review-all-gdds` 标 "consistency only"；`/smoke-check quick` 说明未查覆盖率；Pre-Production 门禁只按报告的 `Mode:` 行计分，1.2.0 之前的报告没有 `Mode:` 行，**一项都不算** |
| `/sprint-plan` 把"yes, go ahead"当成写计划的许可 | 写计划前**再问一次** |
| 两个 `EPIC.md` 被算成两个故事文件 | `/help` 和 `/gate-check` 能正确识别"故事还没建" |

**提升**

- 门禁的结论**对应它真正检查过的范围**；
- 部分检查不会伪装成完整检查；
- 阶段不会越过"没跑成的必检项"。

### 13）平台与数据边角修复

- **Godot 不再导入 `production/`**：新增 [.gdignore](file:///workspace/production/.gdignore)。此前证据截图和 Movie Maker 生成的 `.wav` 会被当作游戏资源导入，默认导出甚至会把它们打进游戏包；

- **`project.yaml` 重复键合并并点名**：第二个 `modes:` 块以前会覆盖第一个，而 schema 检查仍然通过；现在合并，并明确告诉你哪几个键重复；
- **多行 YAML 值按文本读**：`|` 或 `>` 下面的内容不再被当成设置（避免注释里的 `review_mode: full` 真的改掉评审模式）；
- **Windows 写的评审收据在 Linux/macOS 正确读取**：不再把每个文件都读成 CHANGED；
- **`/adopt` 的"帮我找"真的能用**：按标题搜索，指出每份文档该去哪，移动前用 `git mv` 并询问。

### 14）会话启动会告诉你有没有新版本

- 启动时用**一行**提示有新版本，附发布页和关闭方式；
- 只读项目外的**每用户缓存**，后台任务最多每天问一次 GitHub；

## 为什么要这么设计：四个取舍

### 1）"轻"是默认，不是妥协

v1.1.0 的说明里有一句很关键：他们对比过更重的流程，**成本高出数倍，却没有产生更好的结果**，别人接手时也没得到什么。所以默认改成 `minimal`，需要时再用一条命令升到 `standard` 或 `full`。

这解释了 1.1.2 为什么花那么大力气修 minimal 路径：**默认路径必须是真正能走通的那条**。

### 2）确定性的活交给脚本，判断的活留给模型

模型擅长理解、权衡、写代码；不擅长"每次都用同样的方式数一遍 bug、算一遍 sprint、截取同一节 Markdown"。脚本化不是为了取代模型，而是为了**让模型不必重复做机器更擅长的事**。

### 3）失败必须显性

`NOT ASSESSED`、`Mode:` 行、`Reviewed by`、`stamp.txt`、注册表警告——这些设计都在做同一件事：**把"其实没验证"暴露出来**。在一个 AI 协作系统里，最危险的不是报错，而是"看起来通过了"。

### 4）权限应该和实际行为一样窄

技能文本是会被模型执行的。给技能一个裸 `Bash`，等于给它一张空白支票。1.2.0 的做法是：**技能声明它实际运行什么，就只批准什么**；其它一律询问。

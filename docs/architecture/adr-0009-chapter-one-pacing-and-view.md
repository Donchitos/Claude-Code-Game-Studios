# ADR-0009 — 首章升级间隔与生成可见范围

日期：2026-09-16。状态：已实现及本地验证，独立复审待完成。仅用于Campaign开发入口；不替代商业STEAM_SAVE_V2或旧Stage协议。

## 决定

- 首章八任务各自配置xp_base=6、xp_step=4；后七章继续使用全局2/1。第k次升级前累计经验为2k²+4k，普通/精英/目标经验仍为3/12/6。
- 升级候选发布时只扣一次当前门槛；选择成功后在encounter.last_upgrade_tick写入当前tick，后续候选需经过180个active tick。初始值-1表示尚未选择。暂停、选择和机缘不推进tick。积压保留在player.xp中，HUD通过最多99轮有界计算显示待选数量，不增加第二个经验账本。
- 胜利/死亡/超时先于升级发布。04线索机缘等待升级积压清空，间隔期间允许继续战斗；恢复validator接受该等待状态。无积压时机缘可立即显示，不额外套用升级间隔。
- 首章快照升为CAMPAIGN_CHAPTER1_V3；新增tick纳入numeric_bits。内容hash改变，C/D已知进行中档使用原包结束/主动放弃本局后升级；新版拒读前不写双槽。无进行中档保留正常读取。
- 首章动态普通敌/精英/追猎目标使用玩家中心最大1280×720世界视野，加80世界单位视觉余量。候选必须在扩张矩形之外，同时满足原安全距离、方向与障碍规则。相机zoom=max(1, viewport_width/1280, viewport_height/720)，无平滑偏移；实际可见范围始终是该矩形的子集。窗口变化只改变显示，不改变模拟/RNG。敌人视觉半径由目录验证，动态敌人的1.5×radius+10不得超过余量。
- 有限候选失败返回非有限哨兵；分配入口拒绝哨兵。普通遭遇仍按原规则计skipped；追猎保留有界重试/受控错误。开局已存在的Boss/任务锚点是场景目标，不适用动态生成排除。
- 06在0/15/30/45/60秒组织五段敌潮，保留60秒一次精英及92秒撤离；补经验供给而不增加强制时间。01不承诺自然进化，至少一条合法首章路径需获得进化。

## F扩展：升级快照与短关经验（2026-09-16）

- `tutorial & 4`与`last_upgrade_tick >= 0`必须等价；重建numeric_bits也不得绕过该语义校验。保留V3形状。
- 01–05、07–08拾取吸引半径320、速度600；06与后七章保持原值。经验门槛6/4与180 active tick间隔不变。
- 04每个新线索在其位置掉落8经验；08每次阶段突破在Boss位置掉落18经验。均为需实际拾取的可见经验球；已保存的线索数/单调boss_phase阻止恢复重复发奖，跨两阶段发两份。终态不为升级延时。
- 掉落容量满时合并完整经验量到既有球并刷新寿命，保持经验守恒。敌人原始经验值不变。
- 内容变更将E哈希纳入已知旧进行中档拒读路径；仍需旧包结束或主动放弃本局再升级，无进行中档可保留。
- 测试证据按内容hash/套件/唯一run目录隔离；历史证据不得覆盖。恢复旅程逐tick比较完整快照，真实窗口生命周期另有不强制刷新相机的回归。

F证据见[整改与调优报告](../../production/playtest-evidence/2026-09-16-package-f.md)。独立复核仅覆盖F增量，不作为全量设计或商业发布裁决。新玩家试玩SKIPPED_BY_USER，battle_ready=false。

## G实施顺序（2026-09-16）

G1采用已有ANCHOR_PROGRESS，不新增空间触发/快照字段：02/07三个stage value从0/1/2改为0/0/1；第二段offset加90 tick、第三段加45 tick，各行interval45 tick。下一路线的敌人先于下一锚点激活接近；固定锚点免伤、根区关闭和终态优先保持。HP/速度/XP与生成边界不变。目录变化保护F已知进行中档，使用原F包结束或放弃后升级。

G2拟将03初始重叠遭遇归并为真实三段行程；05使用现有CLEANSE_HALF首段触发集中有限增援，不新增等待或空间谓词。G3拟在Boss跨阶段时重置冷却，已发出的落点保留且排空后再发布新阶段完整预警，维持最多2个pending landing。具体实现和证据按G1→G2→G3记录。

### G最终实施确认

- G2：03使用WAYPOINT0/2/3三段、8/12/12共32名额，interval45；05使用CLEANSE_HALF0/0/2/2，同圈两组共享触发tick，第二组offset加30、interval45，6.6秒累计不变。未新增空间触发。
- G3：08可选布尔boss_phase_entry_warning=true。阶段上升将既有entity.timer归零；已发布landings先按原tick/位置执行，排空后发布新阶段完整54tick预警（双落点第二个再延30tick）。zone容量不足时保留timer到下一tick重试，不提前写攻击计数或落点；最多2个pending。致死仍立即结束并清空pending，不强制完成招式。
- 不新增持久字段，V3形状及numeric_bits不变，目录hash绑定新行为。04新增的只是测试观察，原行为不改；攻击计数是预警次数，观察到期落点不等同命中回执。

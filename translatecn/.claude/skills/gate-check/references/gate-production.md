# Gate: Pre-Production → Production

# 门禁：Pre-Production → Production


**Required Artifacts:**

**必需产物：**

- [ ] Vertical slice exists in `prototypes/` with a REPORT.md (run `/vertical-slice`) — **recommended, not blocking**; if absent, surface as CONCERNS
- [ ] First sprint plan exists in `production/sprints/`
- [ ] Art bible is complete (all 9 sections) and AD-ART-BIBLE sign-off verdict is recorded in `design/art/art-bible.md` — where `review_mode` skips that gate (`lean`, `solo`), a `SKIPPED` sign-off line `/art-bible` records stands in for it, and a header still reading `[Not yet reviewed]` on such a project reads "sign-off skipped — [mode] mode", never missing
- [ ] Entity inventory exists at `design/assets/entity-inventory.md` (recommended — run `/asset-spec` with no arguments to generate collaboratively from GDDs + art bible)
- [ ] All MVP-tier GDDs from systems index are complete
- [ ] Master architecture document exists at `docs/architecture/architecture.md`
- [ ] At least 3 ADRs covering Foundation-layer decisions exist in `docs/architecture/`
- [ ] All Foundation and Core layer ADRs have status `Accepted` (not `Proposed`) — stories cannot be unblocked until their governing ADR is accepted
- [ ] Control manifest exists at `docs/architecture/control-manifest.md`
      (generated by `/create-control-manifest` from Accepted ADRs)
- [ ] Epics defined in `production/epics/` with at least Foundation and Core
      layer epics present (use `/create-epics layer: foundation` and
      `/create-epics layer: core` to create them, then `/create-stories [epic-slug]`
      for each epic)
- [ ] Vertical Slice build exists and is playable (not just scope-defined) — **recommended, not blocking**; if absent, surface as CONCERNS
- [ ] Vertical Slice has been playtested with at least 1 documented session — **recommended, not blocking**; if absent, surface as CONCERNS
- [ ] Vertical Slice playtest report exists at `production/qa/playtests/` or equivalent — **recommended, not blocking**; if absent, surface as CONCERNS
- [ ] UX specs exist for key screens: main menu, core gameplay HUD (at `design/ux/`), pause menu
- [ ] HUD design document exists at `design/ux/hud.md` (if game has in-game HUD)
- [ ] All key screen UX specs have passed `/ux-review` (verdict APPROVED or NEEDS REVISION accepted)

- [ ] `prototypes/` 中存在带 REPORT.md 的 Vertical Slice（运行 `/vertical-slice`）——**建议项，不阻塞**；若缺失，作为 CONCERNS 提报
- [ ] `production/sprints/` 中存在第一份冲刺计划
- [ ] 美术圣经已完整（全部 9 个章节），且 AD-ART-BIBLE 签核裁定记录在 `design/art/art-bible.md` 中——在 `review_mode` 跳过该门禁处（`lean`、`solo`），`/art-bible` 记录的 `SKIPPED` 签核行可替代它；而在这种项目上，标题仍写着 `[Not yet reviewed]` 应读作"sign-off skipped — [mode] mode"（签核已跳过），绝不是"缺失"
- [ ] 实体清单存在于 `design/assets/entity-inventory.md`（建议项——不带参数运行 `/asset-spec`，即可从 GDD + 美术圣经协作生成）
- [ ] 系统索引中的所有 MVP 层级 GDD 都已完成
- [ ] 总体架构文档存在于 `docs/architecture/architecture.md`
- [ ] `docs/architecture/` 中至少存在 3 份覆盖 Foundation 层决策的 ADR
- [ ] 所有 Foundation 与 Core 层的 ADR 状态均为 `Accepted`（而非 `Proposed`）——在其主管 ADR 被接受之前，故事无法解除阻塞
- [ ] 控制清单存在于 `docs/architecture/control-manifest.md`（由 `/create-control-manifest` 从 Accepted ADR 生成）
- [ ] `production/epics/` 中已定义史诗，至少包含 Foundation 与 Core 层的史诗（用 `/create-epics layer: foundation` 与 `/create-epics layer: core` 创建它们，然后为每个史诗运行 `/create-stories [epic-slug]`）
- [ ] Vertical Slice 构建存在且可玩（而不仅是定义了范围）——**建议项，不阻塞**；若缺失，作为 CONCERNS 提报
- [ ] Vertical Slice 已被试玩，至少 1 次有记录的会话——**建议项，不阻塞**；若缺失，作为 CONCERNS 提报
- [ ] Vertical Slice 试玩报告存在于 `production/qa/playtests/` 或等价位置——**建议项，不阻塞**；若缺失，作为 CONCERNS 提报
- [ ] 关键界面已有 UX 规格：主菜单、核心玩法 HUD（位于 `design/ux/`）、暂停菜单
- [ ] HUD 设计文档存在于 `design/ux/hud.md`（若游戏有游戏内 HUD）
- [ ] 所有关键界面的 UX 规格都通过了 `/ux-review`（裁定 APPROVED，或 NEEDS REVISION 已获接受）

**Quality Checks:**

**质量检查：**

- [ ] **Core loop fun is validated** — playtest data confirms the central mechanic is enjoyable, not just functional. Explicitly check the Vertical Slice playtest report.
- [ ] UX specs cover all UI Requirements sections from MVP-tier GDDs
- [ ] Interaction pattern library documents patterns used in key screens
- [ ] Accessibility tier from `design/accessibility-requirements.md` is addressed in all key screen UX specs
- [ ] Sprint plan references real story file paths from `production/epics/`
      (not just GDDs — stories must embed GDD req ID + ADR reference)
- [ ] **Vertical Slice is COMPLETE**, not just scoped — the build demonstrates the full core loop end-to-end. At least one complete [start → challenge → resolution] cycle works.
- [ ] Architecture document has no unresolved open questions in Foundation or Core layers
- [ ] All ADRs have Engine Compatibility sections stamped with the engine version
- [ ] All ADRs have ADR Dependencies sections (even if all fields are "None")
- [ ] Manual validation confirms GDDs + architecture + epics are coherent
      (run `/review-all-gdds` and `/architecture-review` if not done recently)
- [ ] **Core fantasy is delivered** — at least one playtester independently described an experience that matches the Player Fantasy section of the core system GDDs (without being prompted).

- [ ] **核心循环的好玩性已验证**——试玩数据确认核心机制令人愉快，而不只是能运行。要明确检查 Vertical Slice 试玩报告。
- [ ] UX 规格覆盖 MVP 层级 GDD 中所有的 UI Requirements 章节
- [ ] 交互模式库记录了关键界面中所用的模式
- [ ] `design/accessibility-requirements.md` 中的无障碍层级在所有关键界面的 UX 规格中都已处理
- [ ] 冲刺计划引用 `production/epics/` 中真实的故事文件路径（不只是 GDD——故事必须内嵌 GDD 需求 ID + ADR 引用）
- [ ] **Vertical Slice 已完整**，而不只是划定了范围——构建演示了端到端的完整核心循环。至少有一个完整的 [开始 → 挑战 → 了结] 循环可运行。
- [ ] 架构文档在 Foundation 或 Core 层没有未解决的待解问题
- [ ] 所有 ADR 都有 Engine Compatibility 章节，并标注了引擎版本
- [ ] 所有 ADR 都有 ADR Dependencies 章节（即使所有字段都是 "None"）
- [ ] 人工验证确认 GDD + 架构 + 史诗彼此连贯（若近期未做，运行 `/review-all-gdds` 与 `/architecture-review`）
- [ ] **核心幻想已交付**——至少一位试玩者（在未被提示的情况下）独立描述出与核心系统 GDD 的 Player Fantasy 章节相符的体验。

**Vertical Slice Validation** (only run these checks if a Vertical Slice was built):

**Vertical Slice 验证**（仅在已构建 Vertical Slice 时运行这些检查）：

- [ ] A human has played through the core loop without developer guidance
- [ ] The game communicates what to do within the first 2 minutes of play
- [ ] No critical "fun blocker" bugs exist in the Vertical Slice build
- [ ] The core mechanic feels good to interact with (this is a subjective check — ask the user)

- [ ] 已有人在没有开发者引导的情况下玩通了核心循环
- [ ] 游戏在开始游玩的前 2 分钟内传达了该做什么
- [ ] Vertical Slice 构建中不存在关键的"好玩性阻塞"缺陷
- [ ] 核心机制的交互手感良好（这是主观检查——询问用户）

> **Verdict rules for Vertical Slice:**
> - **Slice was built AND any validation item is NO** → verdict is automatically FAIL. A broken
>   or unfun vertical slice should not advance to Production.
> - **Slice was built but its report says NOT ASSESSED** (nobody has played it) → it is not a
>   PROCEED, and its validation items were not checked (they are not NO): the Vertical Slice
>   Validation block does not run, so the FAIL rule above does not apply. The gate item is NOT
>   ASSESSED, never passed — and a "not yet" to "a human has played it" means the same.
> - **Slice was not built (skipped)** → downgrade to CONCERNS only, not FAIL. Surface the risk
>   clearly: "Advancing without a validated Vertical Slice increases the risk of late-stage design
>   pivots. Recommended before committing full production scope." The user decides.
> - Skipping is a valid solo dev or time-constrained call. Shipping a broken one is not.

> **Vertical Slice 的裁定规则：**
> - **切片已构建且任一验证项为 NO** → 裁定自动为 FAIL。一个破损或不好玩的 Vertical Slice 不应推进到 Production。
> - **切片已构建但其报告为 NOT ASSESSED**（没人玩过）→ 它不是 PROCEED，其验证项也未被检查（它们不是 NO）：Vertical Slice 验证块不运行，因此上述 FAIL 规则不适用。该门禁项为 NOT ASSESSED，绝不算通过——对"已有人玩过"回答 "not yet" 也是同样含义。
> - **切片未构建（已跳过）** → 仅降级为 CONCERNS，而非 FAIL。清晰地提报风险："在没有经过验证的 Vertical Slice 的情况下推进，会增加后期设计转向的风险。建议在投入完整制作范围之前完成。"由用户决定。
> - 跳过对独立开发者或时间受限的情形是合理的选择。交付一个破损的切片则不是。

## Workflow tier reductions

## 工作流层级削减

The checklist above is the **`full` baseline**. At lower tiers apply the
reduction for the resolved tier; items not named keep their status above.
Reductions only ever *relax* a requirement — `workflow_overrides` is the
only thing that adds one.

上述检查清单是 **`full` 基线**。在较低层级，应用对应已解析层级的削减；未被点名的项目保持上述状态。削减只会 *放松* 要求——`workflow_overrides` 是唯一会新增要求的东西。

- **`full`** — sprint plan + complete (9-section) art bible + epics + UX specs + control manifest all required; **Vertical Slice keeps its Section 2 status** (see note) — its playtest is recommended, 1 documented session with 3+ better
- **`standard`** — epics + sprint plan required; art bible complete + UX specs + control manifest → recommended; **Vertical Slice keeps its Section 2 status**
- **`minimal`** — the minimal floor only: a filled **`design/game-brief.md`** with its build order, and **stories** under `production/epics/` (`workflow-modes.md` — the brief's build order is the plan, so there is **no sprint plan**); everything else **drops** — sprint plan, epics, playtests, art bible, entity inventory, MVP GDDs, the master architecture document, both ADR items, control manifest, the UX items (key screen specs, HUD document, `/ux-review`), and the Vertical Slice items (the slice, its playtest, and the Vertical Slice Validation block) — the two current-build checks below replace them
  **Quality checks at `minimal`:** every check that reads a dropped artifact drops with it — the sprint-plan, architecture, both ADR, GDD-coherence, UX and accessibility checks, and the Player Fantasy check (no GDD holds one). Two still apply, to the current build instead of a slice: **the core loop is fun** (ask the user, or read a playtest note if one exists) and **it runs end to end** — one complete start → challenge → resolution cycle. A "no" to either is FAIL, as a NO on a built slice is at the other tiers; a "not yet" to the fun question means nobody has played the build — NOT ASSESSED.

- **`full`**——冲刺计划 + 完整的（9 章节）美术圣经 + 史诗 + UX 规格 + 控制清单，全部为必需；**Vertical Slice 保持其第 2 节状态**（见注记）——其试玩为建议项，1 次有记录的会话，3 次以上更好
- **`standard`**——史诗 + 冲刺计划为必需；完整美术圣经 + UX 规格 + 控制清单 → 转为建议；**Vertical Slice 保持其第 2 节状态**
- **`minimal`**——仅为 minimal 下限：一份已填写的 **`design/game-brief.md`** 及其构建顺序，以及 `production/epics/` 下的**故事**（`workflow-modes.md`——简报的构建顺序就是计划，因此**没有冲刺计划**）；其余全部**丢弃**——冲刺计划、史诗、试玩、美术圣经、实体清单、MVP GDD、总体架构文档、两项 ADR 项、控制清单、UX 各项（关键界面规格、HUD 文档、`/ux-review`），以及 Vertical Slice 各项（切片、其试玩，以及 Vertical Slice 验证块）——由下面两项针对当前构建的检查取代它们
  **`minimal` 下的质量检查：**每一项读取被丢弃产物的检查也随之丢弃——冲刺计划、架构、两项 ADR、GDD 连贯性、UX 与无障碍检查，以及 Player Fantasy 检查（没有 GDD 承载它）。仍有两项适用，但针对当前构建而非切片：**核心循环好玩**（询问用户，或若存在试玩注记则读取它）与**它能端到端运行**——一个完整的开始 → 挑战 → 了结循环。对任一回答 "no" 即 FAIL，正如其他层级上已构建切片出现 NO 一样；对好玩性问题的 "not yet" 意味着没人玩过该构建——NOT ASSESSED。

> **The Vertical Slice keeps its Section 2 status at `full` and `standard`.** The
> Pre-Production → Production "prototype/Vertical Slice" floor is NOT upgraded to
> blocking by the tier table — the Vertical Slice artifacts stay *recommended,
> not blocking* (absent → CONCERNS, not FAIL) exactly as Section 2 defines, at
> `full` and `standard` alike. At `minimal` they drop — the minimal route never
> builds a slice — and the two current-build checks replace them. The
> genuinely-required floor item at this gate is the **sprint plan** at `standard`
> and `full`, and the **brief's build order plus stories** at `minimal`. The one
> hard rule that binds at every tier: if a Vertical Slice *was built* and any of
> its validation items is NO (at `minimal`, if the current build fails either of
> its two checks), the verdict is FAIL regardless of tier — tier reductions relax
> what must *exist*, never what must *work*.

> **Vertical Slice 在 `full` 与 `standard` 下保持其第 2 节状态。** Pre-Production → Production 的"原型 / Vertical Slice"下限**并未**被层级表升级为阻塞项——Vertical Slice 相关产物仍保持*建议项、不阻塞*（缺失 → CONCERNS，而非 FAIL），恰如第 2 节所定义，`full` 与 `standard` 皆然。在 `minimal` 下它们被丢弃——minimal 路线从不构建切片——由两项针对当前构建的检查取代它们。本门禁中真正必需的下限项，在 `standard` 与 `full` 下是**冲刺计划**，在 `minimal` 下是**简报的构建顺序加故事**。在每个层级都生效的唯一硬规则：如果 Vertical Slice *已构建*且其任一验证项为 NO（在 `minimal` 下，如果当前构建未通过其两项检查中的任何一项），则无论层级如何，裁定为 FAIL——层级削减放松的是必须*存在*的东西，绝不是必须*能工作*的东西。

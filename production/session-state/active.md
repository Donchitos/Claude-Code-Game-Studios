**5 real findings from agent self-test (all fixed same day, all documented in REPORT.md)**:
1. **ADR-0003 correction needed**: `cloud_firestore` 6.6.0 (the actually-resolved version) has NO `Settings(cacheSettings: PersistentCacheSettings(...))` API at all — the ADR's claim that this replaced the "deprecated" `persistenceEnabled`/`cacheSizeBytes` pair is wrong for this package version. The old pair is still the live, correct API.
2. **ADR-0002/ADR-0008 correction needed**: `riverpod` 3.3.2 (actually-resolved) removed `AsyncValue.valueOrNull` entirely (`.value` is now the safe nullable accessor) and moved `StateProvider` to a `legacy` import. Both ADRs prescribe `.valueOrNull` based on pre-3.x semantics.
3. **Tooling friction, scope-cut**: Firebase Auth Emulator on Flutter Web hit a persistent `firebase_auth/api-key-not-valid` error, unresolved after several fix attempts. Real Firebase Auth was cut from the slice (PIN-gated access via PBKDF2 stayed real); Security Rules' ownership check loosened to `true` for the slice only (reward-integrity gate from ADR-0009 kept fully intact and enforced).
4. **Bug in this session's own slice code**: a hardcoded `devParentId` didn't match the real Firebase Auth UID Security Rules check against — silent permission-denied on every op. (Moot after #3's cut, but the underlying lesson stands for whoever wires this for real.)
5. **Real architecture gap surfaced**: `MochiComponent` never actually used its `initialMood` constructor param (hardcoded `PetMood.content`), invisible on first app launch but broke the moment the Flame-canvas-hosting screen was recreated (navigate away and back) — because `GameEventBridge`'s mood-change listener only fires on a *transition*, and ADR-0004's "replay last known state" (`TR-bridge-005`) was only ever implemented as a one-time app-cold-start seed, not a true bus-level replay-to-any-new-subscriber mechanism. Recommend strengthening this for production.
